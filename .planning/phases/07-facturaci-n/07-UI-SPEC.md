## Scope

**Tokens are LOCKED from Phases 1-6** (`lib/core/theme/*`).
- This phase redefines no font, size, weight, spacing or color token.
- It adds **no shared widget to `lib/core/widgets`**.
- New widgets are feature-local (`lib/features/billing/presentation/widgets/`) and are built only from existing tokens and core widgets.
- `AppFilterChip` is reused as-is for single-select choices: the toggle filters, the payment method and the pet.
- `AppStatusChip` and `DosisEstadoChip` are **not** reused, because their enums belong to appointments and doses. The billing state uses the feature-local `EstadoCobroChip`, which has the same anatomy as `DosisEstadoChip` compact and `InsigniaStock`.

**Hard vocabulary rule (D-01):** the string "Factura" / "factura" / "Facturación" **never** appears in any UI string, PDF, file name, WhatsApp text or semantics label.
- The two documents are called **"Cotización"** and **"Cuenta de cobro"**. The area is called **"Cobros"**.
- The mockup title "Facturación" and its toggle "Facturas" are replaced accordingly.
- Internal identifiers (`origen = 'factura'` in SQL) are not user-facing and are exempt.

**Decisions consumed (not re-asked):**
- D-01..D-24 from `07-CONTEXT.md`.
- From Phase 6: `ControlEscritura` / `asegurarEscritura` / `LimitePlanSheet` for read-only colleagues, the no-offline-queue behaviour and the COP formats (`formatearCop`, `parsearCop`, `formatearMiles`), plus `InsigniaStock`, the empty-state anatomy, the skeleton rows, the 88px FAB padding and the disabled-without-opacity rule.
- From Phase 5: the share sheet pattern (`compartir_carne_sheet.dart`), the PDF layout family (`carne_pdf_service.dart`, `historia_clinica_pdf_service.dart`, `compartirPdfProvider`) and the formal "usted" client copy (`firmaVeterinario`, `whatsappUri`, `estadoWhatsApp`).
- From Phase 5.1: the plan logo rule and the "Hecho con VetApp" footer.

**Guiding rules**
1. **Charge in under 30 seconds, one hand.** From "Cobrar" on a completed appointment, a typical consultation charge takes 3 taps: tap a service chip, tap "Emitir cuenta de cobro", tap "Emitir". The client and pet are prefilled, and every action sits in the lower two thirds.
2. **The server is the truth for money, numbers and stock.**
   - The UI shows the total it computed only as a preview. The emitted document shows what the server returns.
   - Numbers (`CC-0001`) are never predicted on the client: a draft shows no number.
3. **Append-only, never edit a cuenta de cobro.**
   - A CC is voided with a reason and reissued (D-10).
   - The UI never offers "Editar" on a CC. Only open quotes are editable.
4. **Status is never color-only.** Every state chip is icon + text, and voided amounts are struck through **and** labelled "Anulada".
5. **No draft is ever lost to a failure** (D-21).
   - On offline or a server rejection the form stays filled.
   - A retry reuses the same idempotency key, so it never duplicates.
6. **Plan and role are different locks**, as in Phase 6.
   - The read-only plan lock uses the padlock and `LimitePlanSheet`.
   - Role limits (admin-only service prices; voiding only by the admin or the author) are hidden or shown read-only with a helper, never with the padlock.

**In scope (surfaces):**
1. `CobrosScreen` (`/cobros`): header, toggle, filters, cards and the FAB.
2. `CobroFormScreen`:
   - `/cobros/nuevo?tipo=cc|cot&clienteId=&mascotaId=&citaId=&consultaId=` for new documents;
   - `/cobros/:id/editar` for open quotes;
   - `/cobros/:id/convertir` to turn a quote into a CC.
3. `ProductoCobroSheet`: the inventory product picker.
4. `CobroDetailScreen` (`/cobros/:id`).
5. `MarcarPagadaSheet`, `AnularCobroSheet` and `EnviarCobroSheet`.
6. `ServiciosScreen` (`/servicios`) and `ServicioSheet`.
7. "Cobrar" entry points:
   - the completar-cita screen;
   - a completed appointment's detail;
   - a consultation in the timeline;
   - the client detail.
8. Más row "Cobros".
9. Optional **cédula** on the client detail form, and **"NIT o cédula"** in Datos de la clínica.
10. The quote / CC PDF layout.
11. Product movement labels for origen `factura` in the inventory history.
12. The read-only padlock treatment on every write control above.

**Out of scope (render nothing):**
- DIAN electronic invoicing and VAT, which must not be mentioned anywhere (D-03);
- partial payments or a balance;
- a discount on the whole document (D-08);
- a public link for billing documents;
- an offline queue;
- charts and the Inicio card or the "Factura" quick action (Phase 8);
- deducting stock when a dose is recorded;
- free-text notes on the document;
- a payments report or export;
- a list of the client's charges inside the client detail (see Planner notes);
- dark-mode re-derivation (Phase 8).

## Spacing Scale

Reused from `AppSpacing`, multiples of 4 only.

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Icon-to-label gap in chips, gap between the title and the meta line in a card, chip vertical padding |
| sm | 8px | Gap between chips, between stepper parts, between stacked action buttons, chip horizontal padding |
| md | 16px | Screen horizontal padding, `AppCard` padding, gap between cards/lines/fields, `TotalCobroBar` padding |
| lg | 24px | Gap between sections (form and detail), sheet top/bottom padding, gap above the action block |
| xl | 32px | Bottom of scroll content (+ safe area), empty-state vertical offset |
| 2xl | 48px | Touch-target minimum: chips, steppers, segmented options, remove-line buttons, sheet buttons, top-bar actions |
| 3xl | 64px (size literal; no `AppSpacing` token, do not invent one) | Empty-state icon circle (`surfaceMuted`, 32px icon) |

**Exceptions (all multiples of 4):**
- 48dp touch targets (`AppSpacing.touchTarget`) for every tap target.
- 56dp minimum height for the Más row "Cobros" and for every `CobroFila`.
- The list scroll content keeps **88px bottom padding** for the extended FAB, as in Phase 6.
- The form scroll content keeps bottom padding equal to the measured `TotalCobroBar` height + 16px, so the last line is never hidden.
- State chip height is 28px (compact, same as `InsigniaStock`).
- The `CobroFila` leading circle is 40px with a 20px icon (same size as `MovimientoTile`).
- The quantity field inside a line stepper is 64px wide.
- The inline progress spinner is 20px.
- Standard icons are 24px.

## Layout & Component Patterns

### 1. Entry points (D-05, D-20)

- **Más row "Cobros":**
  - an `AppCard` row with min height 56, `Icons.receipt_long_outlined`, Body "Cobros" and a trailing chevron;
  - placed **directly after "Inventario"** and before "Recordatorios";
  - no pill and no count;
  - visible to every vet, never locked (reading is always allowed);
  - tap → `context.push('/cobros')`.
- **"Cobrar" buttons (`CobrarBoton`):** outline `AppButton`, `Icons.receipt_long_outlined`, label **"Cobrar"**, 48dp. They appear on four surfaces:
  1. **`CompletarCitaScreen`:**
     - The bottom action block becomes primary **"Finalizar cita"** (unchanged) plus, 8px below it, outline **"Finalizar y cobrar"**.
     - "Finalizar y cobrar" runs the same completion path, including the "Cita completada" snackbar with Deshacer.
     - On success it **pushes** `CobroFormScreen` in CC mode, prefilled with the cita's client and pet (first pet if several, editable) and linked to the cita (`citaId`). It does not go to the agenda.
     - It is disabled under the same rule as "Finalizar cita" (pending pets / in flight).
  2. **Completed appointment detail** (`cita_acciones.dart`, `estado == completada`): outline **"Cobrar"** in the action block, linked to the cita.
  3. **Consultation:**
     - **(a)** The expanded consultation entry in `historia_clinica_timeline.dart` shows, below "Evolución", a `TextButton` **"Cobrar"** (48dp), which opens the form linked to `consultaId`, with the pet and its owner prefilled.
     - **(b)** The "Consulta guardada" snackbar after saving a consultation gets the action **"Cobrar"** (6 s), with the same target.
  4. **Client detail** (`cliente_detail_screen.dart`): outline **"Nueva cuenta de cobro"** (`Icons.receipt_long_outlined`), placed directly after "Agendar cita". It opens the CC form with the client prefilled and no pet.
- **Already charged:**
  - Applies when the cita or consulta already has a non-voided CC linked.
  - Instead of "Cobrar", the surface shows a 48dp tappable row: Label "Cobrada: CC-0012" + `EstadoCobroChip` + chevron, which opens that CC's detail.
  - If the linked CC was voided, "Cobrar" shows again.
  - A cita and a consultation of the same visit are treated as one: a CC linked to either one marks both (see Planner notes).
- **Read-only (plan):**
  - Every "Cobrar" / "Finalizar y cobrar" / "Nueva cuenta de cobro" button swaps its icon for `Icons.lock_outline`, keeps its place, variant and size, and opens `LimitePlanSheet` (LP004).
  - "Finalizar y cobrar" is locked only for the charge. The existing "Finalizar cita" behaviour is unchanged.
- **Routes:** all routes are top-level, outside the shell, with no bottom nav, like `/inventario`. `nuevo`, `:id/editar` and `:id/convertir` are declared before `:id` so they never collide.

### 2. CobrosScreen (`/cobros`)

`AppTopBar(title: 'Cobros', actions: [servicios])`. The action is `Icons.medical_services_outlined` at 48dp, with tooltip/semantics "Servicios y precios"; tap → `context.push('/servicios')`. It is visible to every vet and never locked.

**Fixed header** (does not scroll), 16px page padding, top to bottom:

1. **`ResumenCobrosCard`** (`AppCard`, 16px padding):
   - Two equal columns separated by a 1px `border` vertical divider.
   - Each column shows a Label `textSecondary` caption over a Display amount in `primaryText`, then a Label `textMuted` sub-line:
     - **"Cobrado este mes"**: amount `$ 3.850.000`, sub-line "{Mes} {aaaa}" ("Noviembre 2026");
     - **"Por cobrar"**: amount `$ 450.000`, sub-line "{N} cuentas pendientes" ("1 cuenta pendiente"; "Nada pendiente" when 0).
   - "Cobrado este mes" is the sum of non-voided CCs whose payment date falls in the current America/Bogotá month.
   - "Por cobrar" is the sum of all pending non-voided CCs, of any age.
   - Both values come from the server (one summary RPC) and are **never summed on the client from the visible page**.
   - At text scale ≥ 1.3 the columns stack vertically, separated by a horizontal divider.
   - Semantics: "Cobrado este mes, {monto}. Por cobrar, {monto}, {N} cuentas pendientes."
   - Loading: two `surfaceMuted` skeleton blocks. Error: the card shows "—" in both values and Label "No pudimos cargar el resumen. Desliza hacia abajo para reintentar." (the list still works).
2. **`TipoCobroToggle`** (16px below):
   - A full-width segmented control with two equal options in this order: **"Cotizaciones"** | **"Cuentas de cobro"**.
   - Each segment is 48dp high. The container is pill-shaped, with a 1px `border` and a 1px divider between the options.
   - The selected option has a `primary` fill and `onPrimary` Label; the unselected one is transparent with `foreground` Label.
   - It is single-select, and one option is always selected.
   - **Default: "Cuentas de cobro"**, the frequent case. `?tipo=cot` preselects Cotizaciones.
   - Semantics: a radio group "Tipo de documento" with each option "selected".
3. **Filter chips:** shown **only on "Cuentas de cobro"**.
   - `AppFilterChip`, single-select, 8px gap, 48dp: **"Todas"**, **"Pendientes (N)"**, **"Pagadas"**. The count is omitted when 0. Default: "Todas".
   - Voided CCs appear only in "Todas".
   - Cotizaciones has no filters.

**Scroll area:**
- a `ListView` with 16px horizontal padding, 16px gap between cards and 88px bottom padding;
- `RefreshIndicator` invalidates the list and the summary;
- order: **newest first** by issue date and then by number, descending;
- page size: the **50 most recent** of the selected type. At exactly 50 the footer shows Label `textMuted` "Mostrando las últimas 50." (see Planner notes on pagination).

**FAB:**
- An extended FAB in accent, `Icons.add` + **"Nueva cuenta de cobro"** (or **"Nueva cotización"** on the Cotizaciones tab).
- Tap → `asegurarEscritura` pre-check → `context.push('/cobros/nuevo?tipo=cc|cot')`.
- Read-only: the icon becomes `Icons.lock_outline`, with semantics "Nueva cuenta de cobro, bloqueado, solo lectura", and tap opens `LimitePlanSheet`.

Toggle and filter are local screen state, reset when leaving.

#### 2.1 CobroFila

An `AppCard` in `surface`, 16px padding, min height 56. The whole card is tappable and opens `/cobros/{id}`.

Layout, as one row:
- **Leading:** a 40px `surfaceMuted` circle with a 20px icon in `primaryText`: `receipt_long_outlined` (CC) or `request_quote_outlined` (quote).
- **Middle (`Expanded`, 16px / `AppSpacing.md` from the circle, as in `MovimientoTile`):**
  - Body: the client name (1 line, ellipsis), and for a pet " · {Mascota}".
  - Label `textMuted` meta line: "{número} · {dd/mm/aaaa} · {resumen}".
    - `{resumen}` is the first line's description plus " +{n}" when there are more lines, for example "CC-0012 · 18/08/2026 · Consulta +2".
    - On an open quote the meta line ends instead with " · Válida hasta {dd/mm/aaaa}", or " · Venció el {dd/mm/aaaa}" once that date has passed (computed with `diaBogota`, display only; the state never changes, per D-23).
- **Trailing (right-aligned column):**
  - the amount (Heading, `FittedBox`);
  - 4px below, the `EstadoCobroChip` (none for an open quote).
  - On Anulada the amount is struck through in `textMuted`.

Semantics for the card, as one node: "{Cuenta de cobro|Cotización} {número}, {cliente}, {mascota}, {monto}, {estado}, {fecha}. Abrir detalle."

### 3. CobroFormScreen (new / edit quote / convert)

**Titles:** "Nueva cuenta de cobro" · "Nueva cotización" · "Editar cotización" · "Convertir COT-0004".
- There is a single scroll with 16px page padding and 24px between sections.
- **`TotalCobroBar`** is pinned at the bottom (safe area, rises with the keyboard).
- The screen is reached only after the `asegurarEscritura` pre-check. If LP004 arrives from the server, `LimitePlanSheet` opens over the form and the draft is kept.
- An idempotency key (UUID) is created **once per draft when the screen opens** and reused on every retry of that draft (D-21).

Sections, top to bottom:

0. **Tipo** (new documents only, not edit/convert):
   - A `TipoCobroToggle` with the same widget and order: "Cotización" | "Cuenta de cobro".
   - It is preselected from the entry (`tipo` param; "Cobrar" entries → Cuenta de cobro).
   - Switching keeps the lines and updates the title and the CTA.
1. **Cliente** (required):
   - **Prefilled** (from client detail, cita, consulta or convert): a read-only row in `surfaceMuted`, radius `radiusMd`, min height 48, with Label "Cliente" over Body name. When the entry is **not** linked to a cita or consulta, it has a trailing `TextButton` "Cambiar". When linked, it has no "Cambiar" (the link fixes the client).
   - **Empty:**
     - a tappable field-like row, 48dp, Label "Cliente", Body `placeholder` "Elige el cliente", `Icons.chevron_right`;
     - tap opens a modal sheet "Elegir cliente" with `AppTextField` (`hideLabel`, `prefixIcon: search`, hint "Buscar cliente", autofocus) and a client list (name Body, phone Label `textMuted`) filtered locally, reusing the clients list provider;
     - empty search shows "No encontramos clientes con «{q}»";
     - creating a client from here is **out of scope**.
   - **Validation** on emit: "Elige el cliente."
2. **Mascota (opcional):** shown once a client is chosen.
   - Label "Mascota (opcional)", then a `Wrap` of `AppFilterChip`s, one per active pet of the client.
   - The chips are single-select and **deselectable**: tapping the selected chip clears it.
   - Nothing is preselected unless the entry is prefilled (cita / consulta).
   - If the client has no pets the section is hidden.
   - Linked entries show the pet read-only, like the client.
3. **"Agregar"** (Heading):
   - **Servicios:** Label "Servicios", then a `Wrap` (8px gap) of `ServicioChip`s in the admin's A–Z order, followed by the chip **"Otro"**.
     - `ServicioChip` is a 48dp outline pill (1px `border`, `surface` fill, radius `radiusLg`) with `Icons.add` 16px + Label "{Servicio} · {$ precio}" ("Consulta · $ 50.000"). It wraps to 2 lines at large text scale.
     - Tapping a chip adds a line (quantity 1, the service's default price). If that service is already a line, it increments the quantity by 1 instead.
     - Each tap is announced through a live region: "Consulta agregada. Total {monto}."
     - **"Otro"** adds a free line with an empty description (autofocus) and an empty price.
     - Semantics: "Agregar {servicio}, {precio}".

## PDF Layout (D-04, D-22, D-23, D-24)

     - the clinic **logo** (max 48pt tall), subject to the plan rule of 5.1 D-06: hidden on Gratis, with the name only;

     - "NIT o cédula: {valor}" (only if filled);
     - "{dirección} · {ciudad}" and "Tel. {teléfono}", each line shown only if filled (Figtree 10pt).
   - **Right:**
     - the document title **"Cuenta de cobro"** / **"Cotización"** (Caprasimo 16pt);
     - the number **"CC-0012"** (Figtree bold 12pt);
     - "Fecha: {dd/mm/aaaa}" (10pt).
   - Then a 1pt `primary` rule.
2. **Parties block:**
   - **CC:** "**{Cliente}**" + "C.C. {cédula}" (only if present) under the label "Cliente"; "Mascota: {nombre}" (if any). Then the line **"Debe a: {Clínica}{, NIT o cédula {valor}}"** and **"La suma de: {valor en letras} ({$ 120.000})"**, for example "ciento veinte mil pesos". This follows the customary Colombian cuenta de cobro wording.
   - **Quote:** "Cliente: {nombre}" (+ C.C.), "Mascota: {nombre}".
   - The client's phone is **never** printed (D-24).
3. **Table:**
   - Columns: **Descripción** | **Cant.** | **Valor unitario** | **Subtotal**, with numbers right-aligned.

**Formats:**
- COP is integer only, `$ 120.000`, via `formatearCop` / `parsearCop`.
- Quantities and cédulas use dot thousands separators (`formatearMiles`).
- Dates are `dd/mm/aaaa`; times are `h:mm a. m.`.
- Month names are in Spanish, capitalized ("Noviembre 2026").
- Day and month boundaries use America/Bogotá via `clockProvider` + `diaBogota`, never `DateTime.now()` in widgets.
- Numbers are `CC-0001` / `COT-0001` exactly as the server returns them.
- The client phone is shown in the share sheet as `+57 300 123 4567` (`telefono_co.dart`).

**Tone:** in-app copy for the vet uses informal-neutral "tú"; client-facing copy (WhatsApp, PDF) uses formal "usted". ## Accessibility & Interaction Notes

- **Targets:** every interactive element is at least 48dp:
  - service, payment and pet chips, and the segmented options;
  - steppers and the ✕ remove button;
  - the top-bar actions;
  - share rows (56), cards (56) and the Más row (56);
  - the "Cambiar" and "Cobrada" rows, and the snackbar action "Cobrar";
  - dialog buttons.
- **One-handed reach:**
  - the FAB, `TotalCobroBar` and the detail action block sit in the lower third;
  - the service chips sit mid-screen right under the client;
  - the only top controls are back, "Servicios" and the search fields.
- **Semantics:**
  - `CobroFila` and `LineaCobroTile` are single nodes (see their sections);
  - adding a line announces "{descripción} agregada. Total {monto}." through a live region;
  - stepper buttons read "Aumentar cantidad de {descripción}" / "Disminuir cantidad de {descripción}";
  - the toggle is a radio group, and chips announce their selected state;
  - locked controls read "…, bloqueado, solo lectura";
  - sheets announce their title, with focus on the first field (reason, name) or on the chips (payment);
  - offline/stock banners are live regions;
  - money is read in full ("120.000 pesos"): the `$` amounts get the semantics label `"{n} pesos"`.
- **Never color-only:**
  - state chips carry icon + text;
  - voided amounts are struck through and labelled;
  - the stock error carries icon + text;
  - a price different from the base carries the "Precio base" text.
- **Contrast:**
  - `primaryText` on `warningBg`/`surfaceMuted`/`surface` is ≥ 7:1;
  - `success` on `successBg` follows the Phase 5 precedent;
  - `textMuted` on `surfaceMuted` follows the precedent for Anulada;
  - `onPrimary` on the `primary` segment follows the precedent for primary buttons.
- **Text scale 200%:**
  - the summary columns stack;
  - card trailing amounts shrink with `FittedBox`;
  - line Row 2 wraps (the stepper stays together, and the price field moves below at narrow widths);
  - chips wrap;
  - the total bar keeps the CTA visible (the total shrinks, never clips).
- **Keyboard:**
  - a numeric keypad on quantity, price and cédula fields, and the phone keypad on NIT;
  - "next" moves from the "Otro" description to its price;
  - "done" on price closes the keyboard;
  - money fields select all on focus.
- **Double taps:**
  - the CTA, "Confirmar pago", "Anular" and the share rows ignore taps while in flight;
  - the idempotency key guards emission on the server too (D-21).
- **Animations ≤ 200 ms** (line insertion, chip selection, sheets). Reduce-motion is respected, and counters are not animated.
- **Refresh:** after emit, pay, void or convert, the following are invalidated:
  - the list, the summary and the detail;
  - the cita / consulta / client "Cobrada" state;
  - inventory (list, summary, history) when product lines exist.
- **Offline:** there is no queue. Every failed write keeps the user's input and says it was not saved.
- **Dark mode:** follows the provisional tokens; the state map gets re-derived in Phase 8. The PDF is light-only.

## Planner notes (deltas and open points that touch the plan)

- **WhatsApp + PDF:**
  - `wa.me` deep links cannot carry a file, so the contract uses two rows: the native share sheet with file + caption, and `wa.me` text to the +57 number.
  - If RESEARCH confirms a reliable Android intent targeting a WhatsApp contact with an attachment, row 1 may target the client's chat directly. The copy stays the same; drop the "Elige WhatsApp…" subtitle in that case.
  - `Compartidor` needs a file-sharing method (for example `compartirArchivo(bytes, filename, texto)`) behind the same interface, testable without the platform channel.
- **Routes:**
  - `/cobros`, `/cobros/nuevo`, `/cobros/:id/editar`, `/cobros/:id/convertir`, `/cobros/:id` and `/servicios` are top-level.
  - Declare the literal segments before `:id`.
  - Prefill params: `tipo`, `clienteId`, `mascotaId`, `citaId`, `consultaId`.
- **Link uniqueness:** decide on the server whether one cita/consulta can have at most one non-voided CC (recommended: a partial unique index on `cita_id` / `consulta_id` where not voided). The "Cobrada" row depends on it. A consulta created from a cita should resolve to the same CC (link both ids or look up via the cita).
- **Summary RPC:** one call that returns `cobrado_mes` (Bogotá month, by payment date, non-voided), `por_cobrar` and `pendientes_count`. The client never aggregates.
- **Pagination:** v1 loads the 50 most recent per tab with the footer note. Add "Ver más" only if QA shows clinics exceed 50 per month.
- **Stock error payload:** the RPC should raise a coded error carrying `producto`, `disponible` and `unidad`, so the UI can render "Solo quedan {n} {unidad} de {producto}." and mark the line. Map it in `CobroFailure`, the same way as the `IN001` precedent.
- **`pesosEnLetras(int)`:** a new pure-domain helper (Spanish number words up to 999.999.999, "un millón", "mil", "pesos") with unit tests. It is used only in the CC PDF.

- **Voided PDFs:** the detail hides sharing for voided documents. If the vet needs to resend a voided PDF this can be revisited, and the stamp spec is already defined.
