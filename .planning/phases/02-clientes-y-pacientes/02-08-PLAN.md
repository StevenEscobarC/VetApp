<objective>
Sixth vertical slice: the pet ficha. The vet opens a patient from either list, sees its data and photo, records today's weight in one field, reviews the weight timeline, and retakes the photo with one tap (PAT-02 view, PAT-05, PAT-03 change). Also connects both lists to the ficha and adds photo thumbnails to Pacientes.

Phase Goal (user story): **As a** veterinario independiente, **I want to** registrar, encontrar y mantener al día a mis clientes y sus mascotas reales desde el celular, **so that** pueda llevar mi consulta sin computador, sin recepcionista y sin datos de prueba.

Purpose: The ficha is where Phase 3's clinical history will hang; weight is append-only history (never a mutable column — RESEARCH Pitfall 2) and photos keep the stable-path cache rule.
Output: working pet ficha reachable from Pacientes and from a client's ficha; widget tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ficha -> mascota_pesos INSERT | Vet-typed weight value |
| ficha -> Storage upload/remove | Client-chosen object path; old object removal |
| signed URL -> device cache | Time-limited bearer URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-PESO | Tampering / Repudiation | weight history | mitigate | App exposes only insert; RLS has no update/delete policy; check peso_kg > 0 server-side + parsearPeso client-side |
| T-02-STOR | Information Disclosure | photo path/URL | mitigate | Upload path prefix = mascota.clinicaId from the RLS-filtered row; Storage RLS rejects foreign prefixes; signed URLs 3600 s; cacheKey = path |
| T-02-32 | Tampering | best-effort delete of old photo | mitigate | eliminar only receives the previous foto_path read from the vet's own RLS-visible row; Storage delete policy restricts to own clinic prefix; failures ignored (no data loss) |
| T-02-33 | Information Disclosure | owner navigation by id | accept | duenoId comes from the RLS-filtered mascota row; the client ficha itself is RLS-protected |
</threat_model>
