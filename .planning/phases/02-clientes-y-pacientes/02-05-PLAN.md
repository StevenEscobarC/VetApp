<objective>
Third vertical slice: the vet photographs the pet with one tap while registering it (D-05, PAT-03). Camera -> on-device compression -> private Supabase Storage (clinic-scoped path) -> `mascotas.foto_path`. Builds the reusable `AppPhotoPicker` and Storage datasource that the ficha (Plan 08) and the pet form (Plan 09) reuse.

Phase Goal (user story): **As a** veterinario independiente, **I want to** registrar, encontrar y mantener al día a mis clientes y sus mascotas reales desde el celular, **so that** pueda llevar mi consulta sin computador, sin recepcionista y sin datos de prueba.

Purpose: The photo is how the vet recognises a patient at a glance; it has to be taken in the consultorio in one tap and stored privately (clinic-scoped RLS from Plan 01), with caching keyed by the stable path so signed-URL churn never re-downloads images (RESEARCH Pitfall 1).
Output: camera-first photo in the combined alta, reusable picker/datasource/providers, widget tests proving the cacheKey rule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device camera/gallery -> app memory | Arbitrary image bytes from the device |
| app -> Supabase Storage bucket mascota-fotos | Client chooses the object path |
| signed URL -> CachedNetworkImage | Time-limited bearer URL cached on device |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-STOR | Information Disclosure | upload path / signed URLs | mitigate | Path prefix is the vet's own clinicaId from authProfileProvider (never user input); Storage RLS from Plan 01 rejects other prefixes; signed URLs expire after 3600 s |
| T-02-22 | Information Disclosure | signed URL persisted in DB | mitigate | Only the object path is stored in mascotas.foto_path; grep gate asserts `upload` returns path |
| T-02-23 | Denial of Service | huge camera originals over mobile data | mitigate | image_picker maxWidth 1600/quality 85 + flutter_image_compress 1024/80 JPEG before upload |
| T-02-24 | Tampering | non-image bytes uploaded | accept | Private, clinic-scoped bucket; content-type forced to image/jpeg; only the uploading clinic can read it |
| T-02-25 | Elevation of Privilege | camera permission | mitigate | Runtime pre-flight via permission_handler; permanently-denied path routes to OS settings instead of re-prompting |
</threat_model>
