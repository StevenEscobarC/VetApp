### `supabase/schema.sql` - tabla `clinica_planes` (model, CRUD solo lectura)

**Analog:** `clinica_invitaciones` (L1141-1164) y revokes de Fase 5 (L2008-2019). El bloque nuevo debe ir **al final** del archivo (después de L3283) bajo `-- ===== Fase 5.1: Planes y límites (delta idempotente) =====`, igual que los encabezados de L1050 y L1873.

**Tabla + RLS** (L1141-1164, forma a copiar):
```sql
create table if not exists public.clinica_invitaciones (
  id uuid primary key default gen_random_uuid(),
  clinica_id uuid not null references public.clinicas(id) on delete cascade,
  ...
  created_at timestamptz not null default now()
);
alter table public.clinica_invitaciones enable row level security;

drop policy if exists clinica_invitaciones_select on public.clinica_invitaciones;
create policy clinica_invitaciones_select on public.clinica_invitaciones for select to authenticated
using (public.es_admin_clinica() and clinica_id = public.mi_clinica_id());

-- Sin políticas de insert/update/delete: solo las RPC security definer escriben.
revoke all on public.clinica_invitaciones from anon;
```

**Revoke de escritura a `authenticated`** (L2012-2019):
```sql
revoke all on table public.protocolos_vacunacion from anon;

```
Para `clinica_planes`: policy `select` con `public.es_veterinario() and clinica_id = public.mi_clinica_id()` (patrón L1996-2010, todos los vets lo ven, D-15), `revoke all ... from anon` y `revoke insert, update, delete, truncate ... from authenticated`. Columnas: ver RESEARCH.md "Tabla de plan sin escritura para usuarios".

**Constraint idempotente** (L1060-1065, L1077-1082): usar el bloque `do $$ begin alter table ... add constraint ...; exception when duplicate_object then null; end $$;` para el `check (plan in ('gratis','beta') or pagado_hasta is not null)`.

**Analog:** helpers de 4.1 (L1087-1112) y hardening (L1042-1047).

create or replace function public.es_admin_clinica()
returns boolean language sql stable security definer set search_path = public

  select 1 from public.perfiles

### `supabase/schema.sql` - triggers de límite/solo lectura (middleware)

**Analog de forma:** `citas_validar_update` (L1718-1775):
```sql
create or replace function public.citas_validar_update()
returns trigger
language plpgsql
set search_path = public
as $$
...
  raise exception 'Solo se pueden editar citas pendientes o confirmadas.'
    using errcode = 'check_violation';
...
  return new;
end;
$$;

drop trigger if exists citas_validar_update on public.citas;
create trigger citas_validar_update before update on public.citas
for each row execute procedure public.citas_validar_update();
```
Copiar: `drop trigger if exists ...; create trigger ...` (idempotente) y mensajes en español con `using errcode`. Diferencias obligatorias para 5.1: `security definer` (Pitfall 2), `errcode = 'LP001'..'LP004'` (no existe analog, ver abajo), y `if tg_op = 'DELETE' then return old; end if;` (Pitfall 3).

**Dónde se engancha cada trigger** (hechos verificados):
- `mascotas`: `mascotas_insert` permite INSERT directo (L187-188), así que el trigger `BEFORE INSERT` cubre INSERT directo y las RPC `registrar_cliente_con_mascota` (L271) y `registrar_mascota` (L317) sin tocarlas.
- `clinicas.logo_path`: no hay policy UPDATE; la única vía es `actualizar_clinica` (L3224-3279), que hace `update public.clinicas set ... logo_path = p_logo_path` (L3261-3267). Trigger `BEFORE UPDATE OF logo_path` con `when (new.logo_path is not null and new.logo_path is distinct from old.logo_path)`; quitar el logo (`null`) debe seguir permitido.
- `protocolos_vacunacion`: `guardar_protocolo` (L2282) es definer; el trigger `BEFORE INSERT OR UPDATE` en la tabla lo cubre. `restablecer_protocolo`/`desactivar_protocolo` deben seguir permitidos (D-06), así que el trigger solo bloquea cuando `clinica_id is not null` y la fila es nueva o cambia campos de protocolo (no solo `activo`).
- Guard solo lectura en: `clientes`, `mascotas`, `mascota_pesos`, `citas`, `cita_mascotas`, `consultas`, `dosis_aplicadas`. NO en `carne_enlaces` ni `vacuna_alertas` (A6, D-02).

## Shared Patterns

### Revoke/grant de funciones (nuevo en 5.1 y existente)
**Source:** `supabase/schema.sql` L1042-1048 (hardening), L3155-3157, L3281-3282.
**Apply to:** toda función nueva. Reglas: internas (`_plan_efectivo`, funciones de trigger, `consumir_invitacion`) `revoke all ... from public, anon, authenticated`; RPC de la app (`mi_plan`, `puede_escribir`) `revoke ... from public, anon` + `grant execute ... to authenticated`; `asignar_plan` `revoke ... from public, anon, authenticated` + `grant ... to service_role`. Supabase concede EXECUTE a `authenticated` por defecto en funciones nuevas, así que el `revoke ... authenticated` es obligatorio (Pitfall 1).

### security definer + search_path fijo
**Source:** L1088, L1171, L1260, L2293.
```sql
language plpgsql
security definer set search_path = public
```
**Apply to:** todas las funciones y funciones de trigger de 5.1.

### Idempotencia del delta
**Source:** L1050-1052 y convención de todo el archivo (`create table if not exists`, `create or replace`, `drop policy if exists`/`create policy`, `drop trigger if exists`/`create trigger`, `alter table ... add column if not exists`).
**Apply to:** todo el bloque 5.1 (el archivo se re-ejecuta completo). Las redefiniciones de funciones previas van solo en el bloque 5.1, con comentario `-- redefinida en Fase 5.1`.

### Errores en español con `errcode`
**Source:** L1273, L1327, L1473-1476 (`using errcode = '42501' | '23503' | 'check_violation' | 'P0001'`).
**Apply to:** nuevos mensajes de `LP00x` (texto amable que explica el beneficio, no castiga: "Con Pro registras pacientes ilimitados"). No usar SQLSTATE de clase 40.

### Fecha "hoy" en Bogotá
**Source:** `_hoy_bogota()` L2040-2042; Dart: `lib/core/utils/zona_bogota.dart` y `clockProvider` (`lib/core/data/clock_provider.dart`).
**Apply to:** todo cálculo de vigencia (SQL); Dart solo formatea con `lib/core/utils/formato.dart`.

### Errores de repositorio en dos niveles
**Source:** `supabase_team_repository.dart` L37-41 y L72-76.
**Apply to:** `SupabasePlanRepository` y el argumento nuevo `limite: limitePlanDe(e)` en las failures de los demás repos. Mensajes nuevos van en el `_messageFor` del repositorio, no inline en la UI.

### Gating de UI por rol vía provider
**Source:** `puedeEditarClinicaProvider` / `puedeEditarProtocolosProvider` / `esClinicaMultiVetProvider` (`team_providers.dart` L28-32). El servidor es la autoridad; la UI solo es cortesía.
**Apply to:** `puedeEscribirProvider`, botón de contacto de Mi plan (solo admin, D-15).

### Convenciones Dart (CLAUDE.md)
Archivos `snake_case.dart`; imports relativos (sin barrels); `const` agresivo; `///` en entidades de dominio y widgets reutilizables; dominio en español, plomería en inglés; fechas dd/mm/aaaa; sin precios en la app. Nota de CLAUDE.md desactualizada: Riverpod y go_router sí se usan desde 4.1/5.
