# Phase 5.1 Plan 02: Mi plan vertical slice Summary

**First slice of the plan feature: every vet opens Mas > Mi plan and sees plan name, tags, dd/mm/aaaa date lines and usage counters exactly as `mi_plan()` returns them, with the plan insignia on the Mas row and no money wording anywhere. `flutter analyze` clean, `flutter test` 681/681 passing.**

## Performance

- **Duration:** ~45 min, single session
- **Tasks:** 3 of 3 completed
- **Files created/modified:** 19

## Accomplishments

- `MiPlan` contract (`mi_plan.dart`): enums, `desdeJson` over the 21 keys (unknown enum strings fall back to gratis / sinVencimiento so a server addition never crashes), derived getters `esPrueba`, `pacientesAlTope`, `sinCupoMiembros`, `copyWith`. Dates via `fechaDeBd` (UTC midnight, no TZ shift).
- `SupabasePlanRepository.miPlan()` calls `rpc('mi_plan')` with no parameters (the server resolves the clinic from the JWT) and maps errors in two levels to `PlanFailure` (42501 gets its own Spanish message).
- Providers: `miPlanProvider` returns `null` for a profile that is not an active vet with a clinic and when `planRepositoryProvider` cannot be built; `puedeEscribirProvider` is `true` while loading or on error (server is the authority).
- `plan_textos.dart`: pure functions implementing the UI-SPEC insignia table and the plan-card row 3/4/5 table, including the Gratis-after-trial note, gracia with/without colleagues, Fundador and Beta variants.
- `MiPlanScreen`: read-only notice, plan card (name, Activo / En gracia chip, Prueba / Beta / Fundador tags, vigencia lines), "Uso de tu clinica" (pacientes with 8px bar, veterinarios, logo, protocolos propios), collapsed "Que incluye cada plan" with "Tu plan" tag, skeleton loading and an error card with Reintentar.
- Mas row "Mi plan" with the compact insignia (none while loading or on error), semantics "Mi plan, {insignia}", routed to `/mas/plan` through `masPlanRoutes`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Inconsistent test expectation] 42 of 50 is already 84 %**
- **Found during:** Task 2, first `flutter test` run
- **Issue:** The plan's behavior bullet says planGratis (42 of 50) shows no "Te quedan" helper "below 80 %", but 42/50 = 84 %, which the UI-SPEC rule (80-99 % shows "Te quedan {n}") and the semantics example ("42 de 50 pacientes, 84 por ciento") say must show "Te quedan 8". The implementation follows the UI-SPEC.
- **Fix:** The test asserts "no helper" with 30 of 50 and asserts "Te quedan 8" for the 42 of 50 fixture. The fixture itself keeps 42 / 50 as the plan specified.
- **Files modified:** `test/mi_plan_screen_test.dart`
- **Commit:** `601cb2e`

**2. [Rule 3 - Blocking] Non-const fixtures**
- **Issue:** The CONTRACT shows `planOverrides({MiPlan plan = planBeta, ...})`, but fixtures contain `DateTime.utc(...)` so they cannot be `const` and cannot be a default parameter value.
- **Fix:** `planOverrides({MiPlan? plan, Object? error})` and `FakePlanRepository({MiPlan? plan, this.error})` default to `planBeta` in the initializer. Call sites are identical to the CONTRACT.
- **Files modified:** `test/helpers/fake_plan.dart`
- **Commit:** `7b5c2de`
