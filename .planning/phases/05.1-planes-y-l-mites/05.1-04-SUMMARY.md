# Phase 5.1 Plan 04: Patient-limit slice and shared limit UX Summary

**A Gratis clinic at 50 patients is stopped before any patient form opens by the sheet "Llegaste a los 50 pacientes" (with "50 de 50 pacientes" and a "Ver mi plan" route), a server LP001/LP004 on a stale form opens the same sheet with the typed data intact, and read-only colleagues see a lock on the creation buttons. `flutter analyze` clean, `flutter test` 724/724 passing.**

## Performance

- **Duration:** ~70 min, single session
- **Tasks:** 3 of 3 completed (each RED then GREEN)
- **Files created/modified:** 18

## Accomplishments

- `core/errors/limite_plan.dart` has no imports at all; `core/data/limite_plan_postgrest.dart` is the single place that turns `PostgrestException` (code, falling back to hint) into a `LimitePlan`. `MascotaFailure` implements `ConLimitePlan`, so the domain layer never sees the SDK.
- `LimitePlanSheet`: 64px `surfaceMuted` circle with 32px icon per variant, start-aligned heading (autofocus + header semantics), body, patients-only counter, pinned "Ver mi plan" / "Ahora no" buttons below a scroll area (verified at 200 % text scale). "Ver mi plan" captures the `GoRouter` before popping and pushes `/mas/plan`. Non-admins get the "Pidele al administrador..." sentence (not on the read-only variant, which already says it). No sheet string contains money words (asserted on rendered text for every variant and by grep).
- Gate helpers: `asegurarEscritura`, `asegurarNuevoPaciente` (write check first, then patient cap), `asegurarFuncionPro`, `manejarLimitePlan` (invalidates `miPlanProvider`, fetches a fresh plan, shows the sheet). All fail open on any read error and never read `miPlanProvider` (only `invalidate`).
- `SupabaseMascotaRepository`: all 10 `on PostgrestException` sites now throw `MascotaFailure(_messageFor(e), limite: limitePlanDe(e))`; `_messageFor` returns fixed Spanish copy for LP001/LP004 (and a generic "no incluida en tu plan" for the other kinds), never the raw server text.
- Both forms (`nuevo_cliente_mascota_screen`, `mascota_form_screen` create and edit) call `manejarLimitePlan` before the existing error path, so the sheet opens over the form and controllers stay intact.
- Entry points: "Nuevo cliente" FAB (clientes list), "Nueva mascota" (cliente detail) and "Registrar paciente nuevo" (Vacunar search) pre-check with the plan. In read-only the icon becomes `lock_outline` with semantics "..., bloqueado, solo lectura" and unchanged size/variant. No lock for the 50-patient cap (plan-wide, not a permission).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Stale counter] Invalidate the plan after a successful patient creation**
- **Found during:** Task 3
- **Issue:** The list/detail screens pre-check with the cached `miPlanProvider` value; after creating the 50th patient the cache would still say 49 and the pre-check would allow a doomed attempt (only the server LP001 would stop it).
- **Fix:** `ref.invalidate(miPlanProvider)` in the success path of the nuevo cliente + mascota and the nueva mascota flows (no-op when the provider is not watched).
- **Files modified:** `nuevo_cliente_mascota_screen.dart`, `mascota_form_screen.dart`
- **Commit:** `5e91d19`

**2. [Rule 3 - Blocking] Search sheet gate lives inside the sheet**
- **Issue:** The plan says the 'nuevo cliente' action calls `asegurarNuevoPaciente(context, ref)`, but the action runs in the top-level `showMascotaSearchSheet(BuildContext)` which has no `WidgetRef`.
- **Fix:** The check runs when "Registrar paciente nuevo" is tapped inside `MascotaSearchSheet` (already a `ConsumerStatefulWidget`, no new provider watches); only on allow does it pop `_Eleccion.nuevo()`.
- **Commit:** `5e91d19`

**3. [Plan label mismatch] "Agregar mascota" is "Nueva mascota" in the code**
- The plan and UI-SPEC call the cliente-detail button "Agregar mascota"; the real label is "Nueva mascota". The label was left unchanged (tests and other flows depend on it); the gate and lock treatment are applied to that button.

**4. [Process] Gates do not await the sheet**
- The CONTRACT only fixes the return values. Returning only after the sheet closes left callers' `finally` (loading flag) waiting behind a modal; the gates therefore `unawaited(...)` the sheet. Signatures and return values are as specified.

**5. [Process] dart format touched only files edited in this plan**
- `dart format` on `test/nuevo_cliente_mascota_screen_test.dart` also reflowed a few pre-existing lines in that file (it was not previously formatted). No other unrelated file was formatted.
