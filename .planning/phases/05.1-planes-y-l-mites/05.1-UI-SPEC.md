# Phase 5.1 — UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Mode: `--auto` (no questions asked; every value derived from `05.1-CONTEXT.md`, `05.1-RESEARCH.md` and the locked Phase 1-5 UI-SPECs).

---

## Scope

**Tokens LOCKED from Phases 1-5** (`lib/core/theme/*`). This phase redefines no font, size, weight, spacing or color token and adds **no shared widget to `lib/core/widgets`**. New widgets are feature-local (`lib/features/plan/presentation/widgets/`) and built only from existing tokens and core widgets.

**Decisions consumed (not re-asked):** D-01..D-16 from `05.1-CONTEXT.md`; stack decisions from `05.1-RESEARCH.md` (feature folder `lib/features/plan/`, `LimitePlanFailure` for `LP001..LP004`, `SOPORTE_WHATSAPP` via `--dart-define`, no new packages, UI reads only `mi_plan()`); tokens, 48dp targets, one-accent-CTA-per-screen rule, 64px `surfaceMuted` icon circle, `warningBg` banner pattern (`NotificacionesBanner`), disabled-without-opacity rule, pill badges, "Atendió/Aplicó" tone from `04.1-UI-SPEC.md` and `05-UI-SPEC.md`.

**Guiding rules**
1. **Explain, never punish (CONTEXT specifics).** A limited action never ends in a bare error. It ends in a sheet that states the benefit, reassures that nothing is lost, and leads to Mi plan.
2. **Never show money.** No prices, no COP, no "$", no payment links, no "pagar/comprar/suscribirse/precio/factura" wording anywhere in this phase (Google Play "solo consumo", D-14). The only commercial surface is a WhatsApp contact for the admin.
3. **Server is the authority; UI is courtesy.** The UI reads flags and numbers from `mi_plan()` (`dias_restantes`, `estado`, `puede_escribir`, counts). Dart never computes dates, days left or limits from `DateTime.now()`.
4. **Never block D-02 surfaces.** Carné, link público, PDF, WhatsApp share, vaccine alerts, registrar dosis (by users who can write), agenda view, historia clínica view/PDF are never shown as locked because of the plan.

**In scope (surfaces):**
1. Más row "Mi plan" with plan insignia.
2. `MiPlanScreen` (`/mas/plan`).
3. `PlanBanner` on Inicio (80 % of patient limit; last 7 days of trial / plan / gracia; gracia; read-only).
4. `LimitePlanSheet` — explanatory bottom sheet for limited actions (new patient, subir logo, protocolo propio, invitar sin cupo, colega en solo lectura).
5. `PruebaClinicaSheet` — "Plan Clínica 30 días gratis, sin tarjeta" on first invitation code.
6. Read-only state for colleagues (lock treatment on write actions, Inicio banner, Mi plan status).
7. Inline plan hints on existing screens (Datos de la clínica logo, Protocolos, "Guardar en mi catálogo" switch).

**Out of scope (render nothing):** prices, payment links, in-app payment, plan comparison with prices, upgrade buttons that open a store/URL, admin panel, activation codes, push notifications about plan expiry, hiding the "Hecho con VetApp" footer (D-05), dark-mode re-derivation (Phase 8).

## Layout & Component Patterns

### 1. Más row "Mi plan" (D-16.4)
Placement in `MasScreen`: after "Datos de la clínica", before "Recordatorios" (clinic-level group: Equipo, Datos de la clínica, Mi plan). Same `AppCard` row pattern as siblings (min height 56): `Icons.workspace_premium_outlined`, Body "Mi plan", trailing `PlanInsignia` (compact: pill with icon + Label), then chevron. The insignia is `Flexible` and wraps to a second line at large text scales; the row never clips. Visible to all vets (D-15). Loading: no insignia (row still tappable). Error: no insignia.

Insignia label rules (server provides `plan`, `origen`, `estado`, `fundador`, `dias_restantes`; Dart only formats):

| Situation | Label | Style |
|-----------|-------|-------|
| Gratis | "Plan Gratis" | Gratis |
| Pro / Clínica pagado vigente | "Plan Pro" / "Plan Clínica" | Plan activo |
| Pro / Clínica pagado con Fundador | "Plan Pro · Fundador" / "Plan Clínica · Fundador" | Plan activo |
| Pagado, ≤ 7 días para vencer | "Plan Pro · 5 días" | Últimos 7 días |
| Prueba Pro | "Prueba Pro · 12 días" | Prueba |
| Prueba Clínica | "Prueba Clínica · 12 días" | Prueba |
| Prueba, ≤ 7 días | same label | Últimos 7 días (warning) |
| Beta | "Beta" (Fundador: "Beta · Fundador") | Beta |
| Gracia | "Gracia · 9 días" | Gracia |
| Colega en solo lectura (caller can't write) | "Solo lectura" | Solo lectura (overrides plan label in this row only) |

Day wording: `1` → "1 día", `0` → "último día" (e.g. "Prueba Pro · último día"), `n` → "{n} días".

### 2. MiPlanScreen (`/mas/plan`) (D-14, D-15)
`AppTopBar(title: 'Mi plan')`. Single scroll, `md` horizontal padding, `lg` between sections, bottom `xl` + safe area. Visible to all vets. Top to bottom:

1. **Read-only notice** (only if the caller cannot write): `warningBg` card, `lock_outline`, Label "Tu cuenta está en solo lectura", Body "Puedes ver todo, pero no crear ni editar. Habla con el administrador de tu clínica para activar el plan." Not dismissible.

2. **Plan card** (`AppCard`, `surface`, 16px padding):
   - Row 1: `workspace_premium_outlined` 24px + Heading plan name ("Plan Gratis" / "Plan Pro" / "Plan Clínica" / "Plan Beta") + trailing estado chip (`PlanInsignia`: "Activo" success, "En gracia" warning; Gratis/Beta sin vencimiento show "Activo").
   - Row 2 (tags, `Wrap` 8px gap, only those that apply): "Prueba" (timer), "Beta" (science), "Fundador" (star). A paid plan with Fundador shows only "Fundador".
   - Row 3 (Body): date line. Row 4 (Label `textSecondary`): remaining/consequence line. See table.
   - Row 5 (only Gratis after a trial, Label `textMuted`): "Tu prueba terminó el 31/10/2026. Tus datos están intactos."

   | Situation | Row 3 (Body) | Row 4 (Label) |
   |-----------|--------------|---------------|
   | Gratis | "Plan sin vencimiento" | "Hasta 50 pacientes y 1 veterinario." |
   | Prueba Pro vigente | "Prueba Pro hasta el dd/mm/aaaa" | "Te quedan {n} días. Sin tarjeta." |
   | Prueba Clínica vigente | "Prueba Clínica hasta el dd/mm/aaaa" | "Te quedan {n} días. Sin tarjeta." |
   | Pro / Clínica vigente | "Activo hasta el dd/mm/aaaa" | "Te quedan {n} días." |
   | Fundador sin fecha | "Plan Fundador" | "Sin fecha de vencimiento." |
   | Beta con fecha | "Acceso Beta hasta el dd/mm/aaaa" | "Todo está habilitado durante la Beta." |
   | Beta sin fecha / Fundador | "Acceso Beta completo" | "Todo está habilitado durante la Beta." |
   | Gracia (con colegas) | "Venció el dd/mm/aaaa" | "Tienes {n} días de gracia, hasta el dd/mm/aaaa. Después, tus colegas quedarán en solo lectura." |
   | Gracia (sin colegas) | "Venció el dd/mm/aaaa" | "Tienes {n} días de gracia, hasta el dd/mm/aaaa. Después volverás al plan Gratis." |

   `{n}` text: "Te quedan 1 día" / "Te queda hoy" never "0 días": use "Último día." when `dias_restantes == 0`. All dates `dd/mm/aaaa`, rendered from the server `date` without time-zone conversion.

3. **"Uso de tu clínica"** (Heading) then a column of `UsoContadorTile`s (`AppCard`, 8px gap between tiles):
   - **Pacientes** (`pets_outlined`): Body "42 de 50 pacientes" + 8px bar (Gratis only). Label under bar: `< 80 %` nothing; `80 %–99 %` "Te quedan {n}"; `100 %` "Límite alcanzado: puedes seguir atendiendo, pero no registrar más." Pro / Clínica / Beta: Body "42 pacientes" + Label `textSecondary` "Sin límite".
   - **Veterinarios** (`group_outlined`): Body "1 de 1 veterinarios" (count of active / `miembros_max`); bar only when `miembros_max >= 2`; Label under: full (and `miembros_max >= 2`) "Cupo completo"; Beta "Sin tope". No 80 % warning here (a solo vet is always 100 %).
   - **Logo en carné, PDF y página** (`image_outlined`) — `CaracteristicaTile`: Label right-aligned "Incluido" (`check_circle_outline`, `success`) or "No incluido en Gratis" (`lock_outline`, `textMuted`). If a logo is stored but hidden: "Guardado, oculto en Gratis" (`lock_outline`, `textMuted`).
   - **Protocolos propios** (`tune`): "Incluido" / "No incluido en Gratis"; Label `textSecondary` helper in Gratis: "Los protocolos estándar siguen disponibles."
   Tiles are not tappable (informational); semantics read as one sentence.

4. **"Qué incluye cada plan"** — `Icons.expand_more` disclosure, collapsed by default (same pattern as "Agregar más detalles"), no prices. Expanded: three `AppCard` rows, the row of the current plan tagged "Tu plan" (Label pill):
   - "Gratis" — "Hasta 50 pacientes · 1 veterinario · carné con el nombre de la clínica"
   - "Pro" — "Pacientes ilimitados · 1 veterinario · logo y protocolos propios"
   - "Clínica" — "Pacientes ilimitados · 2, 3 o 5 veterinarios según el tramo · logo y protocolos propios"
   Footer Label `textMuted`: "El carné, la historia clínica, la agenda y las alertas de vacunas están incluidos en todos los planes."

5. **Soporte / contacto block** (`AppCard`, `surfaceMuted`):
   - **Admin and `SOPORTE_WHATSAPP` present:** Label "Activa o cambia tu plan"; Body "Para activar o cambiar tu plan escríbenos por WhatsApp."; Label `textSecondary` "Plan de interés"; `AppFilterChip` row (48dp, single-select) "Pro" | "Clínica", preselected = current plan if it is Pro/Clínica, otherwise "Pro"; Label `textSecondary` "WhatsApp de soporte: +57 3XX XXX XXXX" (number always visible, formatted with `telefono_co.dart`); primary accent **"Escribir por WhatsApp"** (WhatsApp icon treatment, 48dp, full width, 24px above). Tap opens WhatsApp with the prefilled message (see Copywriting). If WhatsApp cannot open: snackbar "No pudimos abrir WhatsApp."
   - **Admin without `SOPORTE_WHATSAPP`** (Play build): number and button are not rendered; Body "Para activar o cambiar tu plan, comunícate con soporte." No accent CTA on the screen.
   - **Non-admin vet:** number and button are not rendered; Body `textSecondary` "Solo el administrador de tu clínica puede pedir cambios de plan. Habla con él para activar o cambiar el plan."

   Hard rule: nothing in the block, the chips or the message mentions price, payment, card, COP or a link to pay.

6. Nothing else is interactive. No "Cancelar plan", no "Mejorar plan" button, no store link.

### 3. PlanBanner on Inicio (D-16.2)
Placement: first child of the Inicio `ListView`, above the "Hola, {nombre}" card, inside the 16px page padding (rounded, not edge-to-edge — Inicio is a card list, unlike Agenda). **At most one banner at a time**, chosen by priority:

1. Solo lectura (caller can't write) — not dismissible.
2. Gracia — not dismissible.
3. Patients at 100 % — not dismissible.
4. Last 7 days of trial / paid plan (`dias_restantes <= 7`, vigente) — dismissible.
5. Patients ≥ 80 % and < 100 % — dismissible.

Members (veterinarios) never produce an Inicio banner (a solo vet is always 1/1); the full-seat case is handled in Equipo (see §5).

Anatomy (`Container`, `warningBg`, 1px `border`, radius `radiusMd`, 16px padding, min height 48dp):
- Leading icon 24px in `warning` color (`info_outline`, `schedule`, `pets_outlined` or `lock_outline` per variant).
- Column: Label title in `primaryText`; Body message in `foreground`, max 2 lines at 1x scale (wraps naturally at larger scales).
- Trailing: `TextButton` "Ver mi plan" (48dp min) → `context.push('/mas/plan')`. Dismissible variants add a 48dp `Icons.close` icon button, semantics "Descartar aviso". The whole banner body is also tappable (opens Mi plan).
- Dismissal is **memory-only** (per app session, per variant key); the banner returns on next launch while the condition holds. Dismissal never hides priority 1-3.

### 4. LimitePlanSheet — explanatory sheet (D-16.3)
A single modal bottom sheet (`showModalBottomSheet`, `isScrollControlled: true`, scrollable body, drag handle, top radius `radiusLg`, `surface` fill, 24px padding). Structure, always the same:
1. 64px `surfaceMuted` circle with a 32px icon (`textSecondary`; `lock_outline` for read-only).
2. Heading title (centered or start-aligned like other sheets: start).
3. Body explanation (benefit first, then reassurance).
4. Optional Label `textSecondary` counter line (patients only).
5. Actions, stacked, 8px gap, 48dp: primary **"Ver mi plan"** (closes the sheet and `context.push('/mas/plan')`) and `TextButton` **"Ahora no"** (closes).

It is opened from two places and renders identically: (a) **pre-check** before the action (flags from `mi_plan()`), so the blocked form never opens; (b) **server fallback** when a write returns `LimitePlanFailure` (race / stale flag) — the sheet opens over the current form and the form data is kept. A raw error message or snackbar is never the only feedback.

For non-admin vets the Body gains a final sentence "Pídele al administrador de tu clínica que active el plan." and nothing else changes ("Ver mi plan" still works: all vets see Mi plan).

### 5. PruebaClinicaSheet — "Plan Clínica 30 días gratis, sin tarjeta" (D-11)
Trigger: admin on Equipo taps **"Generar código"** (Phase 4.1 button) when `prueba_clinica_disponible` is true (plan efectivo Gratis or Pro, no active seat available, trial never used). It replaces the direct generation; the code appears in the same flow right after confirming. Same modal sheet shell as §4.

Content:
- 64px `surfaceMuted` circle, `group_add_outlined` 32px.
- Heading **"Plan Clínica 30 días gratis, sin tarjeta"**.
- Body: "Invita a tus colegas y trabajen juntos con pacientes, agenda y carnés compartidos."
- Three Label rows with `check_circle_outline` (`success`): "Hasta {miembros_max} veterinarios durante la prueba" (number from the server, 5 by default), "Logo y protocolos propios", "Sin tarjeta y sin cobro automático".
- Body `textSecondary`: "Si después no sigues con el plan Clínica, tus colegas pasan a solo lectura tras 15 días de gracia. No pierdes ningún dato."
- Actions: primary **"Activar y generar código"** (`isLoading` while the single atomic request runs) and `TextButton` **"Ahora no"**.
- Success: sheet closes, the `InvitacionCard` shows the new code, snackbar "Prueba Clínica activa hasta el {dd/mm/aaaa}". Failure with `LP002`: swap to `LimitePlanSheet` (miembros). Other failure: snackbar "No pudimos activar la prueba. Intenta de nuevo." and the sheet stays open.
- Shown only the first time (server decides via `prueba_clinica_disponible`); never for non-admins (they cannot generate codes).

**Equipo seat state:** when the plan is Clínica / trial / Beta and seats are full, "Generar código" opens `LimitePlanSheet` (miembros); the Equipo screen also shows Label `textSecondary` under the button "{n} de {m} veterinarios" (same counter as Mi plan).

### 6. Read-only state for colleagues (D-12)
Applies to a vet for whom the server says `puede_escribir == false` (after gracia, beyond the seats of the effective plan). Admin is never read-only.

- **What stays fully usable:** every read screen, historia clínica and its PDF, carné, compartir carné, PDF del carné, link público, vaccine alerts and WhatsApp reminders, Agenda view, search. These controls look and behave normally (D-02).
- **What is locked:** create/edit actions on pacientes, clientes, citas, consultas, dosis, pesos, fotos ("Nuevo paciente", "Agregar mascota", "Nueva cita", "Registrar consulta", "+ Registrar dosis", "Vacunar", edit icons/forms).
- **Lock treatment (no dead buttons, no opacity dimming):** the control keeps its place, variant and 48dp size; its leading icon is replaced by `Icons.lock_outline`; its semantics add "bloqueado, solo lectura". Tapping opens `LimitePlanSheet` (LP004). A primary CTA in a locked state keeps its accent (the screen still has one CTA) — only the icon changes. Form screens are not entered; if a form was already open when the state changed, the server error `LP004` opens the same sheet and keeps the typed data.
- **Indicators:** Inicio `PlanBanner` (priority 1), Más row insignia "Solo lectura", Mi plan read-only notice. No ribbon on every screen.
- **Recovery:** when the admin renews or a seat frees up, the next `mi_plan()` refresh (on Inicio focus, Más open, Mi plan open, after any `LP00x`) clears the lock with no sign-out.

### 7. Inline hints on existing screens (not new screens)
- **Datos de la clínica (logo area), Gratis:** under the logo picker a Label `textMuted` row with `lock_outline`: "El logo se muestra en Pro y Clínica." Tapping the picker opens `LimitePlanSheet` (logo). With a stored-but-hidden logo, the preview stays visible to the admin with Label `textMuted` "Guardado. Se mostrará cuando actives Pro o Clínica." and "Quitar logo" remains available.
- **Protocolos, Gratis:** below the existing info banner, a second `surfaceMuted` row, not dismissible, Label `textSecondary`, `lock_outline`: "En el plan Gratis usas los protocolos estándar. Con Pro creas y editas los tuyos." "Nuevo biológico" keeps its accent and opens the sheet on tap. Custom protocols already created stay readable and keep calculating next doses.
- **Registrar dosis > "Otro" > switch "Guardar en mi catálogo", Gratis:** the switch is **off by default**, helper Label `textMuted` "Disponible en Pro." Toggling it opens `LimitePlanSheet` (protocolos) and stays off. Saving the dose itself is never blocked.
- **Pacientes / alta cliente + mascota, Gratis at 50:** "Nuevo paciente" / "Agregar mascota" stay in place with no lock icon (the limit is plan-wide, not a permission); tap opens `LimitePlanSheet` (patients). Registering a cliente without mascota is not blocked.

## Accessibility & Interaction Notes

- Status is never color-only: every insignia/estado chip has icon + text; progress bars always sit next to the numeric "{n} de {m}" text.
- Contrast: `primaryText` `#643312` on `warningBg` and on `surfaceMuted` >= 7:1 (as in Phases 4.1 / 5); `success` on `successBg` as in Phase 5; banner body uses `foreground` `#201E1D`.
- All touch targets >= 48dp: Más row (56), banner action and dismiss, chips, sheet buttons, disclosure header.
- Semantics: Más row "Mi plan, {insignia}"; banner "{título}. {mensaje}. Ver mi plan" as one node, dismiss separately "Descartar aviso"; counters read "42 de 50 pacientes, 84 por ciento"; locked controls "Nuevo paciente, bloqueado, solo lectura"; sheet is announced with its title and focus lands on the title first.
- Sheets: scrollable at 200 % text scale, never clip the primary button (pinned below the scroll area); dismissible by scrim / drag / "Ahora no"; barrier not blocking for LP004.
- Animations <= 200 ms (disclosure, banner dismiss fade); respect reduce-motion; bar changes without animation when reduced.
- Banner and counters refresh when `miPlanProvider` is invalidated; no polling, no timers.
- Dark mode: follows provisional dark tokens (reconfirm in Phase 8); state map must be re-derived there.
- Multi-vet: all vets see the same plan data; only admin sees the WhatsApp number and button (D-15).
- Privacy/compliance: no payment link, price or checkout in any state; when `SOPORTE_WHATSAPP` is empty the build shows text only (Play-safe fallback from RESEARCH A7).
