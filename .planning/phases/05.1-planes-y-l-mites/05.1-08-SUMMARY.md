# Phase 5.1 Plan 08: Logo and own protocols in Gratis Summary

**In Gratis the logo and own protocols are explained as Pro features (inline hints, pre-check sheets, LP003/LP004 mapped from the server), a stored logo stays visible and removable, and registering a dose is never blocked: only "Guardar en mi catalogo" is. `flutter analyze` clean, `flutter test` 782/782 passing.**

## Accomplishments

- `ClinicaFailure` and `VacunaFailure` gained `limite` (implementing `ConLimitePlan`); the repositories pass `limitePlanDe(e)` and translate LP003 to "El logo es parte de Pro y Clinica." / "Los protocolos propios son parte de Pro y Clinica." and LP004 to the read-only message.
- `GuardarDatosClinica` fetches the fresh plan before uploading a NEW logo and throws `ClinicaFailure(limite: funcion)` without touching storage when `logoPermitido` is false; if the plan read fails it proceeds as before. Removing a logo never consults the plan.
- Datos de la clinica: `lock_outline` hint "El logo se muestra en Pro y Clinica." in Gratis, both pickers open "El logo es parte de Pro" without calling the photo capture, a stored logo keeps its preview with "Guardado. Se mostrara cuando actives Pro o Clinica." and "Quitar logo" saves without any sheet, and an LP003 on save opens the sheet keeping the edited fields. `puedeEditarClinicaProvider` is unchanged.
- Protocolos: second non-dismissible `surfaceMuted` row in Gratis, "Nuevo biologico" opens "Los protocolos propios son parte de Pro", saving a protocol from the edit sheet pre-checks and falls back to the sheet on LP003/LP004 leaving the edit sheet open; Restablecer and Desactivar never open the plan sheet.
- Registrar dosis: switch "Guardar en mi catalogo" off by default in Gratis with "Disponible en Pro.", toggling it opens the protocols sheet and it stays off, `guardarEnCatalogo` is sent false, and the dose is saved. Server LP003/LP004 opens the matching sheet with the form intact.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Pre-check on edit-sheet save**
- **Found during:** Task 2
- **Issue:** The plan's behavior only listed the server fallback for the edit sheet, but the objective says saving a custom/overridden protocol opens the Pro sheet in Gratis. Without a pre-check a Gratis admin would trigger a doomed RPC on every save.
- **Fix:** `_guardar` calls `asegurarFuncionPro(... protocolos)` after validation; `_restablecer` and `_desactivar` do not.
- **Files modified:** `protocolo_edit_sheet.dart`, `protocolos_screen_test.dart`
- **Commit:** `29c6bb1`

**2. [Rule 1 - Test scope] Switch finder in registrar dosis tests**
- **Issue:** `find.byType(SwitchListTile)` matched several switches on the form ("Aplicada en otra clinica", refuerzo).
- **Fix:** Tests use `find.widgetWithText(SwitchListTile, 'Guardar en mi catalogo')`.
- **Commit:** `dddbb07`

**3. [Rule 3 - Acceptance greps] Single-line pre-check calls**
- **Issue:** `dart format` split the multi-line `asegurarFuncionPro(` calls, so the acceptance greps (`asegurarFuncionPro(context, ref, FuncionPro.logo` / `.protocolos`) did not match.
- **Fix:** Extracted a local variable in the logo picker and a `_nuevoBiologico` method in Protocolos so each call fits on one line; behavior unchanged.

Beyond the plan's file list, `test/clinica_contrato_test.dart` got a LP003/LP004 mapping test (it is part of the plan's verify command).
