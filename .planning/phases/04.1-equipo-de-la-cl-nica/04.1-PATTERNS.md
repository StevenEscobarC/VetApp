### `supabase/schema.sql` — delta "Fase 4.1" (migration)

**Analog:** bloque Fase 2 `generar_codigo_vinculacion` (L359-412) + Hardening (L1033-1045). El delta va **al final**, tras Hardening (el archivo se re-ejecuta completo; ver RESEARCH Pitfall 4 para el orden de 11 pasos: columnas -> backfill admin -> constraint -> helpers -> tabla invitaciones -> `consumir_invitacion` -> trigger -> RPCs -> citas/consultas FK+policies+trigger -> grants por columna -> revoke/grant).

**Header de RPC definer + código con CSPRNG** (copiar de `generar_codigo_vinculacion`, L361-412). Variables `v_`, loop de 5 reintentos con `unique_violation`, `gen_random_uuid()` (NO `random()`, NO pgcrypto):
```sql
create or replace function public.generar_codigo_vinculacion(p_cliente_id uuid)
returns table (codigo text, expira_en timestamptz, reemplazo_expirado boolean)
language plpgsql
security invoker
set search_path = public
as $$
...
  if not public.es_veterinario() then
    raise exception 'Solo un veterinario puede generar un código de vinculación.' using errcode = 'insufficient_privilege';
  end if;
  select * into v_cliente from public.clientes where id = p_cliente_id for update;
...
  loop
    v_intento := v_intento + 1;
    v_codigo := lpad((('x' || substr(replace(gen_random_uuid()::text, '-', ''), 1, 8))::bit(32)::bigint % 1000000)::text, 6, '0');
    v_expira := now() + interval '24 hours';
    begin
      update ... ;
      exit;
    exception when unique_violation then
      if v_intento >= 5 then raise; end if;
    end;
  end loop;
```
Adaptar: las RPCs de equipo son `security definer` (no invoker, a diferencia de este analog) con `set search_path = public`; alfabeto de 31 símbolos `ABCDEFGHJKMNPQRSTUVWXYZ23456789` mapeando bytes de `gen_random_uuid()` (saltando índices 6 y 8) con `% 31`; `expira_en = now() + interval '72 hours'`.

**Revoke/grant por RPC** (L408-409 y L1039-1045):
```sql
revoke all on function public.generar_codigo_vinculacion(uuid) from public, anon;
grant execute on function public.generar_codigo_vinculacion(uuid) to authenticated;
-- hardening
revoke execute on function public.crear_perfil_nuevo_usuario() from public, anon, authenticated;
```
`consumir_invitacion` -> `revoke ... from public, anon, authenticated` (sin grant, solo trigger y `unirse_a_clinica`). Re-afirmar al final del delta los revoke/grant de `es_veterinario`/`mi_clinica_id` y `crear_perfil_nuevo_usuario` (el top-of-file los recrea con la versión vieja).

**Helpers a redefinir** (base actual L119-125, agregar `and activo`; `create or replace` DESPUÉS del `alter table perfiles add column if not exists activo ...`):
```sql
create or replace function public.mi_clinica_id()
returns uuid language sql stable security definer set search_path = public
as $$ select clinica_id from public.perfiles where id = auth.uid() and activo $$;
```

Conservar la estructura (`metadata jsonb := new.raw_user_meta_data`, insert `clinicas` + insert `perfiles`) pero: solo leer `codigo_invitacion`/`rol`/`nombre`/`telefono`/`clinica_*`; con código -> `consumir_invitacion(codigo, new.id)` y `rol_clinica='veterinario'`; sin código -> clínica nueva y `rol_clinica='admin'` (D-02); nunca leer `clinica_id`/`rol_clinica`/`activo` de metadata.
