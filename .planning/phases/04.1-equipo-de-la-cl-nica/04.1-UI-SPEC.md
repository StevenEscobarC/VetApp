# Phase 4.1 — UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

**Tokens LOCKED from Phase 1** (`lib/core/theme/*`). This phase redefines no font, spacing or core color token. Its only addition is a small **veterinarian identity palette** (4 values, see Color) used for avatars/markers in multi-vet agendas.

**Decisions consumed (not re-asked):** D-00..D-12 from `04.1-CONTEXT.md`; touchpoints from `MULTI-VET.md` §3.4; patterns, tone and copy conventions from `04-UI-SPEC.md` (AppCard, AppFilterChip, AppButton variants, 48dp targets, Deshacer snackbar, `Sin registrar`).

**Guiding rule (D-00): a clinic with 1 active veterinarian sees ZERO new UI** in Agenda, cita form and historia clínica. The only always-visible additions are: the "Código de invitación" entry in the register flow, the "Equipo" row in Más, and the optional "Matrícula profesional" field in the profile. "Multi-vet mode" = `clinica.veterinariosActivos >= 2`; every multi-vet element below is gated on that single provider (`esClinicaMultiVetProvider`).

**In scope (surfaces):**
1. **Register (vet role):** segmented choice + "Código de invitación" field + "Te unirás a {Clínica}" preview.
2. **Más > Equipo** (`/mas/equipo`): member list, invitations (generate / share / revoke), change role, retire member.
3. **Retiro flow:** confirmation dialog + "Reasignar citas" sheet.
4. **`AccesoRevocadoScreen`** (router state for `activo = false`).
5. **Agenda:** "Mías / Todas" filter, per-vet marker on `CitaCard`.
6. **`CitaFormScreen`:** "Veterinario" selector. **`CitaDetailScreen`:** "Veterinario" info row + "Reasignar".
7. **Historia clínica timeline:** "Atendió: Dr(a). X".
8. **Perfil:** "Matrícula profesional (opcional)".
9. **Optional if cheap (Claude's Discretion in CONTEXT):** admin edits clinic data (Más > Equipo > "Datos de la clínica").

**Out of scope (render nothing):** auxiliar/recepcionista role, multi-clinic selector, approval step after code, email invitations, per-vet filter chips beyond Mías/Todas (see Agenda), per-vet income reports, matrícula verification.

## Typography

Same 4 roles, same 2 weights. **No new sizes or weights.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Figtree) | 1.5 |
| Label | 14px | 600 (Figtree) | 1.5 |
| Heading | 20px | 400 (Caprasimo) | 1.2 |
| Display | 28px | 400 (Caprasimo) | 1.2 |

**Usage mapping:**
- **Display (28px):** the invitation code `K7MQ-4P2X` only (letter-spacing 2px, centered, selectable). Nowhere else.
- **Heading (20px):** `AppTopBar` titles ("Equipo", "Acceso revocado" screen heading, "Reasignar citas"), section headings in Equipo ("Miembros", "Invitaciones"), dialog titles.
- **Body (16px):** member names, descriptive copy, field values, dialog bodies, "Atendió: Dr(a). X" line.
- **Label (14px/600):** role badge text ("Administrador", "Veterinario"), "Activo/Retirado" status, expiry line ("Vence en 71 h"), segmented control text, vet name on `CitaCard`, filter segment labels, field labels, helper and error text.

**Focal points:** Equipo: the invitation code card when one is active, otherwise the "Invitar veterinario" button. Acceso revocado: the heading. Register: the code field when its segment is selected.

## Color

60/30/10 reused verbatim.

| Role | Value | Usage this phase |
|------|-------|------------------|
| Dominant (60%) | `#F5EAD8` `background` | All new screens |
| Secondary (30%) | `#EEE7DB` `surface`, `#DCD3C4` `border`, `#EBDDC5` `surfaceMuted` | Member tiles, invitation card, role badge fill, sheets |
| Accent (10%) | `#C67139` `primary` | See reserved list |
| Destructive | `#DC2626` | "Retirar del equipo" label/confirm, "Revocar" invitation label, error text |

**Accent reserved for (and only):**
1. "Invitar veterinario" primary button on Equipo (the screen's one accent CTA).
2. "Crear cuenta" (existing) on Register; "Crear mi propia clínica" primary on Acceso revocado; "Reasignar" confirm primary in the reassign sheet; "Compartir por WhatsApp" is **outline**, not accent.
3. Selected segment in "Mías | Todas" and in register "Crear mi clínica | Tengo un código" (selection state, same treatment as `AppFilterChip.selected`).
4. Focus ring on edited field (existing), active bottom-nav item (existing).

Accent is never used for: role badges, vet markers, member tiles, expiry text, or more than one primary CTA per screen.

**Veterinarian identity palette (NEW, the only color addition).** Used for `VetAvatar` fill (white initials, Label 14px/600) and a 4px left stripe on `CitaCard` in "Todas" view. Deliberately excludes terracota `primary` so identity never reads as a CTA/selection:

| Index | Value | Name |
|-------|-------|------|
| 0 | `#56633F` | olive (= `success`) |
| 1 | `#3F5A73` | slate blue |
| 2 | `#7A4A6B` | plum |
| 3 | `#8C491A` | `primaryStrong` (brown) |

Assignment: members sorted by `created_at` ascending (stable; the admin/first member is index 0); index = position % 4. All four have >= 4.5:1 contrast with white. **Color is never the sole identifier**: initials ("AG") always shown next to/inside the marker, and the vet's full name appears on detail screens (see Accessibility). The current user's own marker is not special-cased.

**Role/status badges (no new colors):**

| Element | Style |
|---------|-------|
| Admin badge | `surfaceMuted` pill, `primaryText` `#643312` Label, `Icons.admin_panel_settings_outlined` — "Administrador" |
| Veterinario badge | `surfaceMuted` pill, `textSecondary` Label — "Veterinario" |
| Retirado | `AppStatusChip`-style pill in `textMuted` + `Icons.person_off_outlined` — "Retirado" |

| Invitación vencida/usada/revocada | `textMuted` — "Vencida" / "Usada" / "Revocada" |

## Layout & Component Patterns

### 1. Register (vet role)
Existing form, with one addition placed **below the role selector and above name/email**, only when role = Veterinario:
- Segmented control (2 segments, 48dp, `AppFilterChip`-style row): **"Crear mi clínica"** (default selected) | **"Tengo un código"**.
- With "Crear mi clínica": the existing clinic-name field remains and nothing else changes (D-02).
- With "Tengo un código": clinic-name field is replaced by `AppTextField` label "Código de invitación", hint "K7MQ-4P2X", `Icons.vpn_key_outlined`, `TextCapitalization.characters`, auto-formats to `XXXX-XXXX` as typed (hyphen inserted after 4 chars; hyphen/spaces/lowercase accepted on input and normalized), helper "Te lo envió el administrador de tu clínica."
- **Preview (cheap variant, only if `validar_codigo_invitacion` is implemented):** when 8 valid chars are entered, field suffix shows a 20px spinner, then a `successBg` row beneath the field: `Icons.check_circle_outline` + Label "Te unirás a {Clínica}". Invalid/expired: error under the field (see Copy). If the RPC is not implemented, no preview is shown and validation happens on submit; the layout must not depend on it.
- Submit button label stays "Crear cuenta". Errors from the trigger map in `_messageFor` to the Spanish strings below, displayed under the code field (not as a generic top error).
- Segment resets the code field when switched back to "Crear mi clínica".

### 2. Más > Equipo
Entry in `MasScreen`: `AppCard` row, `Icons.group_outlined`, label "Equipo", trailing Label current count ("1 miembro" / "3 miembros") + chevron. **Visible to all vets** (single-vet clinics see it too: it is the entry point to invite the first colleague; this is intentional discoverability, not "new UI in the flow").

`AppTopBar(title: 'Equipo')`. Body scroll, top to bottom:
1. **Heading "Miembros"** then `MiembroTile` list (`AppCard`, `sm` gap): `VetAvatar` 40px · column [Body name "Dr(a). Laura Gómez" (name as stored; prefix "Dr(a). " is NOT added to the list, only in attribution contexts) , Label `textSecondary` "Mat. 12345" if present else nothing] · trailing role badge. Current user's tile shows Label "(Tú)" after the name. Retired members appear in a collapsed section at the bottom "Retirados ({n})" (chevron disclosure, same pattern as "Agregar más detalles"), `textMuted`, no actions.
2. **Admin-only: tapping another member's tile** opens a bottom sheet (large 48dp buttons, member name as Heading): "Hacer administrador" / "Hacer veterinario" (outline, depending on current role) and "Retirar del equipo" (text, `destructive`). Non-admin vets: tiles are not tappable (read-only, no chevron).
   - Own tile (admin): tapping opens the same sheet with only "Dejar de ser administrador" (outline) when another active admin exists; otherwise the sheet shows Body "Eres el único administrador. Nombra a otro antes de dejar el cargo." and no action. Admin cannot retire themselves.
3. **Heading "Invitaciones"** (admin only; entire section hidden for non-admin):
   - If an active (vigente) invitation exists: `InvitacionCard` (`AppCard`, `surfaceMuted`): Label "Código de invitación", **Display code `K7MQ-4P2X`** centered, Label expiry "Vence el 04/10/2026 · 3:15 p. m. (en 71 h)", then row of two outline buttons: **"Compartir"** (`Icons.share_outlined`, opens native share sheet with message below; also offers WhatsApp via `lanzador_externo`) and **"Copiar"** (`Icons.content_copy_outlined`, snackbar "Código copiado"), then text button **"Revocar código"** (destructive label; opens a confirm dialog, see Dialogs). Only one active invitation is shown at a time in the UI (generating a new one while one is active asks first, see below).
   - If none: Body `textSecondary` "No hay códigos activos. Genera uno para invitar a un colega."
   - **Primary CTA "Invitar veterinario"** (`Icons.person_add_alt_outlined`, accent) pinned at the bottom of the screen (same pattern as Agenda's "Nueva cita"), admin only. Tap -> generates a code (spinner on button), the `InvitacionCard` appears at top of the section with `scrollIntoView`, snackbar "Código generado". If an active invitation exists the button label is "Generar código nuevo" and tapping shows a dialog (see Dialogs) because the old one is revoked.
   - History of used/expired invitations: collapsed disclosure "Historial de invitaciones" listing rows `{código} · Usada por {Nombre} 02/10/2026` / `Vencida` / `Revocada` in `textMuted`. Optional; if cut, nothing else changes.
4. **Non-admin footer:** Label `textMuted` "Solo los administradores pueden invitar o retirar veterinarios."
5. **(Optional) "Datos de la clínica"** row (admin only) -> simple form: nombre, ciudad, dirección, teléfono, "Guardar cambios" primary. Non-admin: not shown.

**Share message (fixed, Spanish, tú-neutral to colleague):** "Hola, te invito a unirte a {Clínica} en VetApp. Regístrate como veterinario, elige «Tengo un código» e ingresa: {K7MQ-4P2X}. El código vence el {dd/mm/aaaa} a las {h:mm a. m.} y sirve una sola vez."

### 3. Retiro de un miembro
Flow from the member sheet -> "Retirar del equipo":
1. **Confirmation `AlertDialog`** (see Copy). Actions: text "Volver", destructive text "Retirar".
2. On confirm: `retirar_miembro` runs (spinner). Result returns the count of future open citas.
   - 0 citas: snackbar "{Nombre} ya no tiene acceso" and tile moves to "Retirados".
   - >= 1: opens **"Reasignar citas" bottom sheet** immediately (non-dismissible by scrim; has "Más tarde"). Heading "Reasignar citas", Body "{Nombre} tiene {n} cita(s) próximas sin atender. ¿A quién se las asignamos?"; single-select list of remaining active vets (`VetAvatar` + name, 56dp rows, radio trailing; the current admin preselected); primary **"Reasignar {n} citas"**; text "Más tarde". "Más tarde": snackbar "Las citas quedan sin reasignar; búscalas en la agenda de {Nombre}." — and they stay visible in "Todas" with the retired vet's marker + Label "Sin atender" (retired vet marker rendered with `textMuted` outline and strikethrough-free initials, tooltip "Veterinario retirado"). They remain reasignable one by one from `CitaDetailScreen`.
3. Retiring is immediate and has no Deshacer (access is revoked server-side); re-adding requires a new invitation (stated in dialog body).

### 4. AccesoRevocadoScreen (`activo = false`)
Full-screen, no bottom nav, no back; `background`, content centered (offset `2xl`), `SafeArea`:
- 64px circular `surfaceMuted` container with `Icons.lock_outline` 32px in `textMuted`.
- Heading "Ya no tienes acceso a {Clínica}" (centered).
- Body (centered, `textSecondary`) "El administrador te retiró del equipo. Tus consultas y registros anteriores permanecen en la clínica con tu nombre."
- Primary (accent) **"Crear mi propia clínica"** -> small inline form on same screen (field "Nombre de tu clínica", button "Crear clínica") calling `crear_mi_clinica`; success routes to Inicio with an empty clinic.
- Outline **"Tengo un código de invitación"** -> field "Código de invitación" + "Unirme" (same formatting/error behavior as Register; calls `unirse_a_clinica`).
- Text button **"Cerrar sesión"**.
- Shown on next app launch or whenever any request returns the revoked state; no polling UI.

### 5. Agenda (multi-vet mode only)
- **Filter row** inserted directly under the week header (above the day strip): 2-segment control **"Mías | Todas"** (each 48dp tall, equal width, `radiusLg`, selected = `primary` fill + `onPrimary`, unselected = `surface` + `border`). Opens on **"Mías"** every time (D-08); selection is not persisted between sessions. Hidden entirely when 1 vet.
- **Day strip counts** follow the active filter ("Mías": my citas only).
- **`CitaCard` additions (multi-vet mode only):**
  - In "Todas": a 4px left stripe in the assigned vet's palette color and a Label row at the top-right of content, before the status chip: `VetAvatar` 24px + Label "{Nombre de pila}" (e.g. "Laura"). 
  - In "Mías": no marker (all cards are mine; avoids noise). 
  - Retired vet's citas: marker uses `border` color + Label "Sin atender" in `warning`.
- **Overlap Label** "Se cruza con {Nombre}" only appears among citas of the **same** vet (D-09); no cross-vet overlap hints.
- **"Todas" empty state** copy: Heading "Sin citas este día", Body "La clínica no tiene citas este día." ("Mías" keeps the Phase 4 copy.)
- **"Recordar a todos los de mañana"** counts only the citas shown by the active filter; in "Todas" the sheet lists each cita with its vet's name in Label and signs each message with that cita's assigned vet (D-10), no extra UI.
- Banner "Próxima" and notification logic consider **my** citas only regardless of filter.

### 6. CitaFormScreen
- New section **"Veterinario"** (multi-vet mode only), placed **after "Dónde" and before "Notas"** (low priority: default is correct for 95% of cases). Layout: Label section title; a tappable `AppCard` row (48dp+) `VetAvatar` 40 + Body "Dr(a). {Nombre}" + Label `textSecondary` "(Tú)" if self + trailing `Icons.keyboard_arrow_down`. Tap opens a bottom sheet "Asignar a" with radio rows (56dp, `VetAvatar` + name + "(Tú)"), active members only, current selection checked, closes on pick. Default = creator ("Tú"). In edit mode, preselected = current assignee.
- Retired vets never appear. Selecting another vet changes the free-slot suggestion and overlap check to that vet's agenda (D-09); the suggestion Label recomputes.
- Single-vet: section not rendered, no hidden field difference.
- If the creator assigns the cita to another vet, success snackbar: "Cita agendada para Dr(a). {Nombre}". Otherwise unchanged "Cita agendada".

### 7. CitaDetailScreen
- Multi-vet mode: info block gains row **"Veterinario"** (Label heading) with `VetAvatar` 24 + Body "Dr(a). {Nombre}" (+ " (Tú)"); non-terminal citas also show text button **"Reasignar"** (`Icons.swap_horiz`) beside the row opening the same "Asignar a" sheet; success snackbar "Cita reasignada a Dr(a). {Nombre}" with Deshacer.
- Single-vet: row not shown.
- WhatsApp preview/message uses the assigned vet's name (D-10); no UI change beyond the message text (see Copy).

### 8. Historia clínica timeline
- Each consulta card gains a Label line (`textSecondary`) at the bottom: **"Atendió: Dr(a). {Nombre}"** with `VetAvatar` 24 leading **only in multi-vet mode**.
- In single-vet mode the line is **not shown** (D-00), **except** when the consulta's author is a *retired* vet or differs from any current member: then the line always appears so authorship is never lost. This also covers a clinic that went from 2 vets back to 1.
- Retired author: "Atendió: Dr(a). {Nombre} (retirado)" with name in `textMuted` for "(retirado)".
- Matrícula appears next to the name only in documents (carné/PDF, later phases), not in the timeline.

### 9. Perfil / Matrícula
- In the profile editing screen add `AppTextField` label "Matrícula profesional (opcional)", hint "Ej. 12345", `Icons.badge_outlined`, `TextInputType.text`, max 20 chars, helper "Se mostrará en tus documentos, como el carné de vacunación." No validation beyond trim; empty allowed; never blocks save. Read-only display elsewhere: "Mat. 12345" or hidden when empty (not "Sin registrar" in Equipo tiles; in the profile screen the empty field simply shows the hint).

## Accessibility & Interaction Notes

- Every icon-only control has Spanish `Semantics`/tooltip: "Copiar código", "Compartir código", "Más acciones", "Veterinario retirado".
- `VetAvatar` exposes semantics label "Dr(a). {Nombre completo}" so color/initials are never the only cue; the "Mías | Todas" control exposes "Mostrando: Mías, seleccionado".
- Invitation code is selectable text and announced character-by-character separated by hyphen group ("K 7 M Q, 4 P 2 X"). Alphabet excludes 0/O/1/I/L; input normalizes case.
- All touch targets >= 48dp (segments, tiles, sheet rows, buttons).
- Expiry countdown computed in America/Bogotá; "en N h" rounds down, switches to "en N min" under 1 h; 0 -> "Vencida".
- Haptics: none. Animations <= 200 ms (code card reveal, filter switch); respect reduce-motion.
- Dark mode: still provisional (Phase 1 note); vet palette values are not re-derived for dark here, reconfirm in Phase 8.
- Realtime revoke: no polling UI. The Acceso revocado screen is reached when a request fails with the revoked state or on next launch.
