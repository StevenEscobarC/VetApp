# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

**Design tokens are LOCKED from Phase 1** (`lib/core/theme/*`, approved in `01-UI-SPEC.md`) and reused by Phases 2–3. This phase redefines no color, font, or spacing token. It adds one feature area (`lib/features/appointments/presentation/**`) and makes three small changes to shared/existing UI.

**Decisions consumed (not re-asked):** D-01..D-19 from `04-CONTEXT.md`. Where this document says "(D-xx)" the behavior is locked there; this file only fixes the visual/interaction form.

**In scope (screens/surfaces):**
1. **`AgendaScreen`** (`/agenda`, replaces `ComingSoonScreen`) — day strip LUN–DOM, hourly list, week navigation, "Próxima" banner, notification-denied banner, "Recordar a todos los de mañana".
2. **`CitaCard`** (feature-local widget) — direct actions: WhatsApp, Cómo llegar, Completar, state buttons.
3. **`CitaFormScreen`** (`/agenda/nueva`, `/agenda/:id/editar`) — nueva/editar cita.
4. **`CitaDetailScreen`** (`/agenda/:id`) — detalle + all actions.
5. **Completar flow** (`CompletarCitaScreen`, `/agenda/:id/completar`) — one consulta per mascota, skip, "Completar sin consulta".
6. **Overlays:** overlap-warning dialog, notification permission rationale dialog, cancel-confirmation dialog, undo snackbars, reminder-batch progress sheet.
7. **Más > Recordatorios** setting screen (15/30/60/120).
8. **Phone UX (D-16):** soft-validation helper text in client forms, WhatsApp disabled state.
9. **Integration entry points (D-07):** "Agendar cita" button on `MascotaDetailScreen` and `ClienteDetailScreen`; `ConsultaFormScreen` receives `citaId` and prefills anamnesis (D-19).

**Required changes to shared / already-shipped UI:**
- `AppStatus` gains `noShow` -> chip label "No asistió" (see Color). `solicitada` gets **no** enum value or UI this phase.
- `ClienteDetailScreen` and `MascotaDetailScreen`: "Agendar cita" is added as an **`AppButtonVariant.outline`** button (the "Nueva consulta" / "Guardar cambios" button keeps the one accent CTA slot on those screens).
- Phone fields in `NuevoClienteMascotaScreen` / cliente edit: add helper text per Copywriting (D-16). No layout change.

**Out of scope (render nothing, not even disabled):** estado "Solicitada" UI; swipe gestures on cards (D-11); WhatsApp template editor; "agendar control en N días"; multi-vet filters; Google Calendar; recurring cites; offline queue; per-cita reminder override; month grid view; dashboard "próximas citas" (Phase 8).

## Spacing Scale

Reused from `AppSpacing` (xs..xxl) — multiples of 4 only; the single 64px value below is a local widget constant, not a new token.

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Icon-to-label gap in action buttons, count badge inner padding, gap between day-strip label and number |
| sm | 8px | Gap between stacked cards in the hourly list, gap between action buttons in a card, gap between chips (Wrap spacing/runSpacing) |
| md | 16px | Screen horizontal padding, `AppCard` inner padding, gap between form fields, day-strip horizontal padding |
| lg | 24px | Gap between form sections (Cliente / Mascotas / Cuándo / Dónde / Notas), gap between hour marker blocks |
| xl | 32px | Gap above "Guardar cita" / bottom of scroll content (plus safe-area) |
| 2xl | 48px | Touch-target minimum for this phase's action buttons, stepper buttons, day-strip cells (see Exceptions); empty-state vertical offset |
| (local) | 64px | Large time-stepper display block height (hora sugerida) — NOT an `AppSpacing` token (scale stops at xxl=48); declare as a local constant in the widget |

**Exceptions:**
- **Touch targets in this phase are 48dp minimum** (project principle "≥48dp"), stricter than the existing `AppSpacing.touchTarget = 44`. Executor uses a local `const _minTap = 48.0` (= `AppSpacing.xxl`) for: card action buttons, ±15 min steppers, day-strip cells, week chevrons, state buttons, banner action buttons, radio/chip rows of Recordatorios. `AppFilterChip` (44 min height) is used as-is for motivo/duración chips because they sit in a `Wrap` with `sm` spacing; do not shrink them.
- Day-strip cell width: `(screenWidth - 2*md) / 7`, minimum 44dp wide x 64dp tall (7 cells fit 360dp: 360-32 = 328/7 ≈ 46.8dp). Height 64 is a multiple of 4.
- Hourly list gutter (hour label column): fixed 64px wide.
- Radii reuse `AppSpacing.radiusSm/Md/Lg` (8/12/16); cards `radiusMd`, chips/day cells `radiusLg`.

## Typography

Same 4 roles, same 2 weights (400, 600). **No new sizes or weights.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Figtree) | 1.5 |
| Label | 14px | 600 (Figtree) | 1.5 |
| Heading | 20px | 400 (Caprasimo) | 1.2 |
| Display | 28px | 400 (Caprasimo) | 1.2 |

**Usage mapping:**
- **Display (28px Caprasimo):** only the suggested time in `TimeStepper` ("10:30 a. m." large readout between the −15/+15 buttons) — this is the one place a number must be read at a glance with thumbs. Not used elsewhere.
- **Heading (20px Caprasimo):** `AppTopBar` titles ("Agenda", "Nueva cita", "Editar cita", "Cita", "Completar cita", "Recordatorios"); week range label ("28 sep – 4 oct"); the selected-day date heading above the list ("Hoy, mié 30/09"); day number inside each day-strip cell; empty-state headings; dialog titles.
- **Body (16px Figtree/400):** client/mascota names in the card, motivo, dirección, notes, form field values, dialog/snackbar body, helper copy in banners.
- **Label (14px Figtree/600):** hour marker ("10:30 a. m."), day abbreviation ("LUN"), per-day count badge number, `AppStatusChip` text (existing), button labels in card actions, form field labels/section labels ("Cliente", "Mascotas", "Motivo", "Duración"), "Próxima: …" banner text, helper/error text under fields (error in `destructive`).

**Time/date formats (Colombia, America/Bogota UTC-5, `intl` locale `es_CO`):** hour "10:30 a. m." (with narrow-space and periods, never 24h); date "dd/mm/aaaa" (`formatearFecha`); short day "mié 30/09" (`ddd dd/mm`, lowercase day); duration "30 min" / "1 h" / "1 h 30 min".

**Focal points:**
- `AgendaScreen`: the selected-day hourly list; the "Próxima" banner (when today is selected) is the secondary anchor. The selected day cell is the strongest chrome element.
- `CitaFormScreen`: the `TimeStepper` readout (Display) after cliente/mascota selection.
- `CitaDetailScreen`: client + mascota names (Heading) and the status chip directly beneath.

## Color

60/30/10 split reused verbatim from `AppColors`.

| Role | Value | Usage this phase |
|------|-------|------------------|
| Dominant (60%) | `#F5EAD8` `background` | Screen background of all new screens |
| Secondary (30%) | `#EEE7DB` `surface` + `#DCD3C4` `border`; fields `#EBDDC5` `surfaceMuted` | `CitaCard` and banners backgrounds, unselected day cells, `AppTextField` fills, hour-gutter rule lines (`border`) |
| Accent (10%) | `#C67139` `primary` | See reserved list below |
| Destructive | `#DC2626` `destructive` | "Cancelar" state button label/icon, cancel-confirmation dialog confirm action, field error text, `cancelled` status chip (already mapped) |

**Accent reserved for (and only):**
1. "Nueva cita" primary button on `AgendaScreen` (the screen's one accent CTA — floating/bottom button, see Layout).
2. "Guardar cita" primary button on `CitaFormScreen`.
3. Selected day cell fill in `DayStrip` (same selected treatment as `AppFilterChip.selected`; it is a selection state, not a CTA) and the "hoy" indicator ring/dot on the unselected current day.
4. Selected motivo / duración / reminder-lead chips (`AppFilterChip.selected`, existing behavior).
5. "Completar y registrar consulta" primary button on `CompletarCitaScreen`, and "Guardar consulta" on `ConsultaFormScreen` (unchanged, existing).
6. Focus ring on the currently edited field (existing); active bottom-nav item (existing); `completed` status chip color (already mapped in `AppStatusChip`).
7. The ±15 min buttons are **not** accent (outline).

Accent is never used for: card backgrounds, the WhatsApp/Cómo llegar/Confirmar buttons (outline / text), banners, or more than one primary CTA per screen. On `CitaDetailScreen` the accent slot belongs to **"Completar cita"** (see Interaction Contract); all other actions are outline/text.

**Status chip mapping (existing + new):**

| Estado | Chip label | Color | Icon |
|--------|-----------|-------|------|
| pendiente | Pendiente | `warning` `#D97706` | `schedule_outlined` |
| confirmada | Confirmada | `success` `#56633F` | `check_circle_outline` |
| completada | Completada | `primary` `#C67139` | `task_alt_outlined` |

Status is always icon + label, never color alone (existing rule). Cards in estado cancelada/no_asistió render at full contrast but with the client name in `textMuted` and **no** primary-looking actions (only "Deshacer"-style reopen — see states). Completed/cancelled/no-asistió cards sort in time order with the rest; they are never hidden.

Note: no new color tokens. "Recordatorio enviado" uses `textMuted` text + `Icons.done_all` in `success`.

## Layout & Component Patterns

### AgendaScreen layout (top to bottom)
1. `AppTopBar(title: 'Agenda')`. Actions: none (keeps focus on the strip). 
2. **Notification-denied banner** (conditional, D-13): `NotificacionesBanner` — `surface` card with `warningBg` tint, `Icons.notifications_off_outlined` in `warning`, Label "Recordatorios desactivados", Body "Activa las notificaciones para que te avisemos antes de cada cita.", text button "Activar" (opens app settings), min 48dp. Persistent (no dismiss X) while permission denied; not an error state. Never accent.
3. **Week header row:** `chevron_left` (48x48) · Heading week range "28 sep – 4 oct" · `chevron_right` (48x48). A text button "Hoy" (Label, min 48) appears at the trailing edge **only** when the selected day is not today or the visible week is not the current one; tapping it returns to today's week with today selected (screen always opens on Hoy, D-08). Horizontal swipe on the strip also changes week (additive to chevrons; chevrons are the accessible path).
4. **`DayStrip`:** 7 cells LUN–DOM (Mon first). Each cell (`radiusLg`, 64dp tall): Label day abbreviation, Heading day number, below it a **count indicator**: if count > 0 a small pill with Label number (e.g. "3") 16dp min height in `surfaceMuted` (selected cell: `onPrimary` text on `primaryStrong` pill); if 0 nothing is drawn but vertical space is reserved. Semantics label: "Lunes 29, 3 citas". Selected = `primary` fill + `onPrimary` text; today unselected = 2px `primary` border; others `surface` + `border`. Cancelled citas are not counted.
5. **Selected-day heading** (Heading): "Hoy, mié 30/09" for today, "Mañana, jue 01/10" for tomorrow, else "vie 02/10". Trailing Label summary "4 citas" / "1 cita" / "Sin citas".
6. **"Próxima" banner** (`ProximaBanner`, only when selected day is today and ≥1 non-terminal future cita exists): `AppCard`, Label "Próxima: Luna 10:30 a. m. · en 25 min", tap opens that cita's detail. Hidden if no upcoming cita today. "en N min" updates each minute while screen is visible (≥60 min -> "en 1 h 10 min").
7. **"Recordar a todos los de mañana"** (D-15): shown **only when the selected day is tomorrow** (Bogotá) and it has ≥1 cita in estado pendiente/confirmada. `AppButtonVariant.outline`, `Icons.chat_outlined`, full width, 48dp. Label shows count: "Recordar a todos los de mañana (4)". Citas already marked "recordatorio enviado" are excluded from the count; if all are sent the button becomes a non-interactive Label line "Todos los recordatorios de mañana enviados" with `done_all`.
8. **Hourly list:** vertical list, grouped by hour. Left gutter (64px) with Label hour "10:00 a. m." aligned to the top of the first cita starting in that hour; to the right, `CitaCard`s stacked `sm` apart. Hours with no cita are NOT rendered as empty rows (fricción cero: no scrolling through blank hours); gaps are implied by the hour labels and a thin `border` vertical rule in the gutter. If two citas overlap, they stack vertically and the later one shows a Label "Se cruza con {Nombre}" in `warning` with `Icons.warning_amber_outlined`.
9. **"Nueva cita" primary button:** `AppButton` primary with `Icons.add`, pinned at the bottom above the bottom nav (inside `SafeArea`, `md` padding, scrolling content gets bottom padding 48+16 so the last card is never hidden). It is the screen's one accent CTA. Pre-fills the date with the selected day.

### CitaCard
`AppCard`, padding `md`. Whole card tappable (min 48 height already satisfied) -> `CitaDetailScreen`; action buttons inside capture their own taps.

Content rows:
1. Row: Label time range "10:30 – 11:00 a. m." (start–end, end suffix only once if same meridiem; otherwise both) · spacer · `AppStatusChip`.
2. Body (16px/400): mascota name(s) joined "Luna y Rocky" (3+: "Luna, Rocky y 1 más"); second line Label `textSecondary`: cliente name · motivo ("María Pérez · Vacunación").
3. Modality row (Label, `textSecondary`): `Icons.home_outlined` + dirección (1 line, ellipsis) for domicilio; `Icons.storefront_outlined` + "En consultorio" otherwise.
4. If `recordatorio_enviado_at != null`: Label `textMuted` with `Icons.done_all` in `success`: "Recordatorio enviado 29/09 6:15 p. m.".
5. **Action row** (below a `border` divider, `sm` gap, wraps onto 2 rows if needed; each button min 48x48): shown actions depend on estado:
   - `WhatsApp` (`AppButtonVariant.text`, `Icons.chat_outlined`, label "WhatsApp") — hidden for terminal estados (completada/cancelada/no_asistió). Disabled with explanation for fixed-line numbers (see states).
   - `Cómo llegar` (text, `Icons.directions_outlined`) — only when domicilio.
   - `Completar` (outline, `Icons.task_alt_outlined`) — pendiente/confirmada only. (Outline on the card because a list of N cards must not hold N accent buttons.)
   - Overflow of state changes: **inline "Cambiar estado" row is NOT on the card**; the card exposes `Confirmar` (text, only if pendiente) next to Completar. `No asistió` and `Cancelar` live in the detail screen and are also reachable from the card via one `MoreVert` icon button (48x48, tooltip "Más acciones") that opens a bottom sheet with large buttons: "No asistió", "Cancelar cita", "Editar". No swipe gestures (D-11). Rationale: keeps the card to max 3 visible actions on a 360dp-wide screen.
   - Terminal estados show a single text button "Deshacer" only for 10 seconds via snackbar (see below); afterwards the card shows only "Ver detalle" implicit via tap, and the detail screen offers "Reabrir cita" (text) for cancelada/no_asistió.

### CitaFormScreen (nueva / editar)
Single `SingleChildScrollView` (no stepper), `AppTopBar(title: 'Nueva cita' | 'Editar cita')`. Section order, `lg` between sections:

1. **Cliente** (Label section title):
   - `ClienteSearchField`: `AppTextField` with `Icons.search`, hint "Buscar cliente por nombre o teléfono", instant results (reuses `lib/core/data/busqueda.dart` behavior from Phase 2) rendered as a list of `AppCard` rows (name, phone; min 48 height) directly under the field; max 5 visible, scrollable.
   - Last row always: `AppButtonVariant.text` "+ Nuevo cliente y mascota" (`Icons.person_add_alt_outlined`), pushes `NuevoClienteMascotaScreen` (alta combinada, D-04) in "return result" mode; on return the cliente + mascota are selected and the form keeps all other entered values.
   - Once chosen: collapses to a selected-client row (name, phone, `Icons.close` to change; 48dp).
   - If opened from ficha (D-07): cliente (and mascota) preselected; the search field never shown, only the selected row with "Cambiar".
2. **Mascotas** (only after cliente): `MascotaMultiSelect` — list of the cliente's mascotas as selectable rows (checkbox leading + photo avatar 40dp + nombre + especie), min 56 height; at least one required. If the cliente has exactly one mascota it is preselected. Row at end: text button "+ Agregar mascota" (existing `MascotaFormScreen` with `clienteId` preset).
3. **Motivo** (Label): `Wrap` of `AppFilterChip`: Consulta general (default selected) · Vacunación · Control · Desparasitación · Baño/peluquería · Cirugía · Otro. Selecting a chip sets the default duration (D-01). Default durations (prescriptive): Consulta general 30 min, Vacunación 15 min, Control 30 min, Desparasitación 15 min, Baño/peluquería 60 min, Cirugía 90 min, Otro 30 min. "Otro" reveals an `AppTextField` "¿Cuál es el motivo?" (single line).
4. **Duración** (Label): `Wrap` of `AppFilterChip` 15 min · 30 min · 45 min · 1 h · 1 h 30 min · 2 h (the chip matching the motivo default is preselected; user may tap another). No free-typed minutes.
5. **Cuándo:**
   - Date row: tappable `AppCard`-style row (48 height) showing "mié 30/09/2026" + `Icons.calendar_today_outlined`; opens `showDatePicker` (themed). Default = selected day on Agenda (or today). Past dates allowed (registering a past visit) without warning.
   - `TimeStepper`: centered row `[ − 15 min ]  10:30 a. m.  [ + 15 min ]`. Buttons 64x64 outline (`radiusLg`), icons `Icons.remove` / `Icons.add` with Label "15 min" beneath; center readout Display 28px. Initial value = **first free slot** of the chosen day (D-06): first start time ≥ now (rounded up to next 15 min, for today) or ≥ 8:00 a. m. (for other days) that doesn't overlap an existing non-cancelled cita for the chosen duration; Label helper beneath "Primer hueco libre sugerido" shown only while value equals the suggestion; changes to "Hora elegida" once the user steps. Long-press on a stepper button repeats. Hold range 6:00 a. m. – 10:00 p. m. (buttons disable at the bounds). Below the stepper, Label `textSecondary` "Termina a las 11:00 a. m.".
6. **Dónde:** `SwitchListTile`-style row (48 min height) "A domicilio" with `Switch`. When ON: reveals `AppTextField` "Dirección" prefilled from `clientes.direccion` (editable for this cita only; helper "Solo para esta cita"); if `clientes.direccion` is empty the field is empty and focused, and "Guardar cita" stays disabled until a dirección is typed. When OFF: nothing shown (consultorio).
7. **Notas** (optional, collapsed behind the existing "Agregar más detalles" disclosure pattern from `MascotaCamposSection`, chevron `keyboard_arrow_down/up`): `AppTextField` "Notas" multiline.
8. **"Guardar cita"** primary (accent) at the bottom, `xl` above. **Disabled (not hidden), reduced opacity** until: cliente, ≥1 mascota, fecha y hora (always present), and dirección when domicilio is on. `isLoading` spinner on submit.
   - On save: if overlap → **overlap dialog** (below) before persisting. If first cita ever and notification permission undecided → **permission rationale dialog** after a successful save (D-13), then OS prompt.
   - Success: pop to `AgendaScreen`, selecting the cita's day, snackbar "Cita agendada". Edit success: "Cita actualizada".
   - On back with edits in progress: no confirm dialog (consistent with all create forms).

Edit mode: same layout; mascotas, fecha/hora, duración, motivo, domicilio, dirección, notas editable; **cliente is not changeable** (shown as read-only row) to preserve linked history; editing a terminal-estado cita is not offered.

### CitaDetailScreen
`AppTopBar(title: 'Cita')`, action `Icons.edit_outlined` (tooltip "Editar cita", only for pendiente/confirmada). Body scroll, top to bottom:
1. Heading mascota name(s) ("Luna y Rocky"), below `AppStatusChip`.
2. Info block (Label heading + Body value pairs): Cuándo ("mié 30/09/2026 · 10:30 – 11:00 a. m."), Cliente (name; phone with tap -> not a separate action), Motivo, Dónde ("En consultorio" | dirección), Notas (or "Sin registrar" `textMuted`), Recordatorio ("Enviado 29/09 6:15 p. m." | "Sin enviar").
3. Mascotas list rows (avatar + nombre) tappable -> ficha de la mascota; when completada, each row shows "Consulta registrada" (Label `success`) or "Sin consulta" (`textMuted`).
4. **Action area (stacked full-width buttons, 48dp, `sm` gap)**, by estado:
   - pendiente: **"Completar cita" (primary, accent — screen's one CTA)**, "Confirmar" (outline), "WhatsApp" (outline), "Cómo llegar" (outline, domicilio only), "No asistió" (outline), "Cancelar cita" (text, `destructive` label).
   - confirmada: same without "Confirmar".
   - completada: "Ver historia clínica" (outline -> mascota ficha) only; if some mascota lacks consulta: "Registrar consulta pendiente" (outline).
   - cancelada / no_asistió: "Reabrir cita" (outline; returns to pendiente) + no other state buttons; WhatsApp hidden.
   Every state change shows the **Deshacer snackbar**.

### Completar flow (`CompletarCitaScreen`)
Reached from "Completar" on card/detail. `AppTopBar(title: 'Completar cita')`.
- Heading "¿Registrar la consulta?" ; Body "Puedes registrarla ahora o completar la cita sin consulta."
- **Mascota list (D-18):** one `AppCard` per mascota in the cita: avatar, nombre, status Label on the right: "Pendiente" (`textMuted`) / "Consulta registrada" (`success` + check) / "Omitida" (`textMuted`). Each card has two 48dp buttons: **"Registrar consulta"** (outline -> `ConsultaFormScreen(mascotaId, citaId)`, anamnesis prefilled with motivo + notas, D-19) and **"Omitir"** (text). After returning from the form with a saved consulta, that card flips to "Consulta registrada" and its buttons are replaced by `Icons.check_circle_outline`.
- Single-mascota citas use the same screen (one card); no special-case bottom sheet.
- Bottom area: primary (accent) **"Finalizar cita"** button, enabled only when every mascota is Registrada or Omitida; on tap sets estado completada and pops to Agenda with snackbar "Cita completada" + **Deshacer**. Directly above it a text button **"Completar sin consulta"** (visible always while at least one mascota is Pendiente): marks all remaining as Omitida and completes immediately (one tap, no extra confirm — Deshacer covers mistakes).
- System back with a partially filled flow: stays safe — already-saved consultas persist (append-only); cita is not completed until "Finalizar cita"; no confirm dialog.
- `ConsultaFormScreen` addition: when `citaId` is present, anamnesis field is **expanded by default and prefilled** ("{motivo}. {notas}"), editable; no other change; a Label chip row at the top "Cita del mié 30/09 · 10:30 a. m." (`surfaceMuted` pill, non-interactive) shows the link.

- Notification text (system tray): title "Cita en {n} min" / "Cita en 1 hora"; body "{Mascota(s)} — {Cliente} a las {h:mm a. m.}{ · A domicilio}". Tapping opens `CitaDetailScreen`.

### WhatsApp & phone (D-14..D-16)
- **Individual button:** opens `wa.me/{numero}?text={mensaje formal con usted}` via `url_launcher` (external app). On launch, mark `recordatorio_enviado_at` immediately and show snackbar "Marcado como recordatorio enviado" with action "Deshacer".
- **Disabled state (fixed line / non-mobile):** the "WhatsApp" button renders disabled (reduced opacity, still 48dp) with, beneath the action row, Label `textMuted` "Este número parece un teléfono fijo; no se puede enviar WhatsApp." Tapping the disabled button shows the same text in a snackbar (so the reason is discoverable). No phone at all: button disabled, text "Este cliente no tiene teléfono." with text button "Agregar teléfono" -> client edit.
- **"Recordar a todos los de mañana" (D-15):** tap opens a **bottom sheet progress** (not a full screen): Heading "Recordar a los de mañana", Body "Vamos de uno en uno: abre WhatsApp, envía el mensaje y vuelve aquí."; list of citas with row states Pendiente de enviar / Enviado (`done_all`, success) / Sin WhatsApp (fixed line, `textMuted`, skipped automatically); primary (accent; the sheet is its own surface and holds its own single accent CTA) **"Enviar a {Cliente}"** advancing to the next; text "Marcar como enviado" (manual fallback when return from WhatsApp isn't detected) and text "Cerrar". When the last one is done: Body "Listo, recordaste a {n} clientes." with "Cerrar".
- **Phone soft validation (clientes forms):** inline helper under the phone `AppTextField` (Label, `warning`, never blocking): "Parece que este número no es un celular colombiano. Revísalo o guárdalo así." Shown after blur only when the normalized value isn't `3XXXXXXXXX` (10 digits starting with 3) and has no foreign "+" prefix. Helper (neutral, `textMuted`) when empty/valid: "Ej. 300 123 4567". Saved value is normalized to `57XXXXXXXXXX`; displayed formatted "+57 300 123 4567". Numbers with other "+" indicativo are respected and show no warning.

### Overlap warning dialog (D-09)
`AlertDialog`: Title (Heading) "Se cruza con otra cita"; Body "Se cruza con {Mascota} a las {10:00 a. m.}. ¿Agendar igual?" (multiple: "Se cruza con 2 citas: {Luna 10:00 a. m.}, {Max 10:15 a. m.}. ¿Agendar igual?"); actions: text "Cambiar hora" (returns to form, focus on stepper) and primary "Agendar igual". Non-blocking by design; no destructive coloring. Used for create and edit (edit button text: "Guardar igual").

### Cancel confirmation
Cancelar is the only state change with a dialog (dismissing a client's booking is higher-consequence and also frees a slot). `AlertDialog` Title "¿Cancelar esta cita?", Body "{Mascota(s)} el {ddd dd/mm} a las {h:mm a. m.}. La cita quedará como cancelada y no se borra.", actions: text "Volver", destructive text button "Cancelar cita". After confirm: snackbar "Cita cancelada" + "Deshacer". Other state changes (Confirmar, Completar sin consulta, No asistió) have no dialog; they use Deshacer.

### Undo snackbar (D-11)
`SnackBar`, duration 6 s, action label "Deshacer" (min 48 touch via `SnackBarAction`). Restores the previous estado (and, for completar sin consulta, nothing else since consultas are append-only and never created by that path). Only the most recent change is undoable; a new change replaces the snackbar. For "Finalizar cita" in Completar flow, Deshacer reverts only the cita estado, never saved consultas.

## Accessibility & Interaction Notes

- Every icon-only control (`chevron`, `MoreVert`, stepper, close) has a `Tooltip`/`Semantics` label in Spanish ("Semana anterior", "Semana siguiente", "Más acciones", "Restar 15 minutos", "Sumar 15 minutos", "Quitar cliente").
- `DayStrip` cells expose "Lunes 29, 3 citas, seleccionado"; list time ordering is by `fecha_hora` ascending.
- Status never by color alone (icon + label). Contrast: all text on `background`/`surface` uses existing AA-passing tokens; `warning` text (`#D97706`) is only used at Label 14px/600 over `warningBg`/`surface` alongside an icon.
- "Hoy" and day boundaries are computed in America/Bogotá, not device-local timezone.
- Haptics: none required. Animations: ≤200 ms for banner/section reveal and selected-day change; respect reduce-motion.
- Dark mode: still derived/provisional (Phase 1 note); not re-verified here.
