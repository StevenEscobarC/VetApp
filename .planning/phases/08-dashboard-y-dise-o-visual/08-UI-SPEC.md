## Scope

**Tokens are LOCKED from Phases 1-7** (`lib/core/theme/*`).
- This phase redefines no font, size, weight, spacing or color token.
- It adds **no shared widget to `lib/core/widgets`**.
- It adds **one pure helper** to `lib/core/utils/formato.dart`: `formatearCopCorto(int pesos)` (see §3.2), with unit tests.
- New widgets are feature-local (`lib/features/home/presentation/widgets/`) and are built only from existing tokens and core widgets.

**Hard vocabulary rule (Phase 7 D-01, D-10):** the string "Factura" / "factura" / "Facturación" **never** appears in Inicio or anywhere the sweep touches. The mockup's third quick action "Factura" is **"Cobro"**. The mockup's metric "Nuevos" is **"Pacientes nuevos"**, and its link "Ver todas" is **"Ver agenda"** (D-08).

**Mockup elements deliberately dropped:**
- the "Sincronizado" chip (no offline sync; out of scope);
- the bell icon button (no notification center; push is out of scope);
- the per-row WhatsApp button in "Próximas citas" (the reminder lives in the cita detail and `RecordatoriosScreen`; a second entry here would duplicate it and crowd a 360dp row).

**Decisions consumed (not re-asked):**
- D-01..D-20 from `08-CONTEXT.md`.
- From Phase 7: D-17 "Cobrado este mes" rule (ingresos), `formatearCop` / `formatearMiles`, the money tone `primaryText`, the offline wording family "Sin conexión. … Inténtalo de nuevo cuando tengas señal.", the 64px empty-state icon circle, the per-block skeleton anatomy.
- From Phase 5.1: `ControlEscritura` / `asegurarEscritura` / `iconoEscritura` / `LimitePlanSheet`, `PlanBanner`, the "read is never locked" rule (D-12).
- From Phase 5: `VacunasPendientesCard` and the global "Vacunar" flow (`showMascotaSearchSheet`), D-14 clinic-wide alerts.
- From Phase 6: `StockBajoCard` (D-08).
- From Phase 4.1: `VetAvatar`, `indicesColorVetProvider`, `esClinicaMultiVetProvider`, `miembrosActivosProvider`, the retired-vet treatment.
- From Phase 4: `AppStatusChip`, `hora12`, `encabezadoDia`, `aBogota`, the `/agenda/:id` detail route and `/citas/nueva`.

**Guiding rules**
1. **Glance in 3 seconds, act in 1 tap.** Opening the app answers "how is my month going and who is next", and every common creation is one tap away in the top half of the screen.
2. **Blocks fail alone.** Header, metrics, quick actions, próximas citas and each alert card load and fail independently. One failure never blanks Inicio.
3. **Reading is never locked.** Read-only colleagues see every number and every cita. Only the 4 quick actions and "Agendar cita" carry the padlock.
4. **Status is never color-only.** State chips are icon + text; the vet mark is initials + color + semantics name.
5. **The server is the truth for numbers.** The client never aggregates metrics; it renders `inicio_resumen()` as returned.
6. **The sweep changes looks, never behaviour** (D-19).

**In scope (surfaces):**
1. `InicioScreen` (`/inicio`), rewritten: greeting header, `PlanBanner`, metrics row, quick actions, próximas citas, alert cards, pull-to-refresh, states.
2. Feature-local widgets in `lib/features/home/presentation/widgets/`:
   - `InicioEncabezado` (greeting header);
   - `MetricasMes` (row/stack of 3) and `MetricaTarjeta`;
   - `AccesosRapidos` and `AccesoRapido`;
   - `ProximasCitas` and `ProximaCitaFila`;
   - `BloqueError` (the per-block error card);
   - `BloqueSkeleton` helpers.
3. Removal of the standalone "Vacunar" `AppButton` (folded into quick actions, D-10).
4. Removal of `ComingSoonScreen` and every "Próximamente" string (D-17).
5. The DASH-04 sweep of every feature, governed by the **Sweep Rules** section.

**Out of scope (render nothing):**
- charts, month-over-month comparison, per-vet metrics;
- a global consultations list (the Consultas card does not navigate);
- push notifications, the "Sincronizado" chip, offline mode;
- exportable reports;
- a dark-mode redesign (D-18: only contrast is verified);
- any flow or rule change in existing screens (D-19).

`Scaffold` with **no `AppTopBar`** (the greeting header replaces it, as in the mockup). Body:

- Vertical gap between visible blocks: `lg` (24px). A hidden block (banner, alert card) contributes **no** gap: build the children list conditionally, or have the block own its bottom gap only when visible. No double gaps, no trailing gap.

### 3. Metrics row (`MetricasMes`, DASH-01, D-01..D-06)

#### 3.1 Layout

- **Row layout (default):** `Row` of 3 `Expanded` `MetricaTarjeta`, gap `sm` (8px), equal heights (`IntrinsicHeight` or `crossAxisAlignment: stretch` with min height 96).
- **Stacked layout:** when the available width is `< 320` logical px **or** `MediaQuery.textScalerOf(context).scale(16) > 20.8` (text scale above 1.3), the 3 cards stack full-width with gap `sm`. Each stacked card is one row: kicker left (Label), number right (Display, right-aligned), chevron after the number when tappable. Min height 64.
- No section heading above the metrics (mockup has none); the kickers carry the meaning. The month scope is in the semantics label and the kicker of the first card is not "del mes" to keep the 3 kickers short (see Copy).

`MetricaTarjeta` (row layout) anatomy, inside `AppCard(padding: all(md))`:

```
[kicker Label 14/600 textMuted, maxLines 2]   [chevron_right 16px textMuted]   ← only when tappable
(xs gap)
[number Display 28 primaryText, FittedBox scaleDown, left-aligned]
```

#### 3.2 Numbers and formats (D-05)

| Card | Kicker | Value source | Format | Example |
|------|--------|--------------|--------|---------|
| Consultas | "Consultas" | `consultas_mes` | `formatearMiles(n)` | "42", "1.250" |
| Ingresos | "Ingresos" | `ingresos_mes` (same rule as Cobros "Cobrado este mes": CC `pagada` with `pagada_el` in the Bogotá month; voided and quotes never count) | `formatearCopCorto(pesos)` | "$ 850.000", "$ 3,8 M" |
| Pacientes nuevos | "Pacientes nuevos" | `pacientes_nuevos_mes` (mascotas created in the Bogotá month) | `formatearMiles(n)` | "7" |

**`formatearCopCorto(int pesos)`** (new, `lib/core/utils/formato.dart`; deterministic so tests do not depend on layout):
- `pesos < 1.000.000` → `formatearCop(pesos)`: "$ 0", "$ 85.000", "$ 999.999".
- `1.000.000 ≤ pesos` → millions **truncated** (never rounded up, so income is never overstated) to one decimal, decimal comma, and the `,0` dropped, then " M": 1.000.000 → "$ 1 M"; 3.849.999 → "$ 3,8 M"; 12.500.000 → "$ 12,5 M"; 999.950.000 → "$ 999,9 M".
- `pesos ≥ 1.000.000.000` → whole millions with thousands grouping: 1.250.000.000 → "$ 1.250 M".
- A narrow no-break space is **not** used; a regular space after "$" and before "M", consistent with `formatearCop`.
- Negative input never occurs (server sums paid totals); assert `pesos >= 0`.

#### 3.3 Taps (D-04)

| Card | Tap | Visual affordance |
|------|-----|-------------------|
| Consultas | **none** (no global list; deferred) | no chevron, no ripple, `AppCard(onTap: null)` |
| Ingresos | `context.push('/cobros')` (CobrosScreen opens on its default "Cuentas de cobro" tab) | 16px chevron, ripple, ≥48dp (the whole card) |
| Pacientes nuevos | `context.go('/pacientes')` (switches to the Pacientes tab) | 16px chevron, ripple |

Read-only colleagues: all 3 render and navigate identically (D-06). No padlock.

#### 3.4 States

| State | Rendering |
|-------|-----------|
| Loading | Each of the 3 cards renders its **real kicker** and a 28px × 56px skeleton bar (`surfaceMuted` / `mutedDark`, `radiusSm`) in place of the number. Taps are disabled while loading. |
| Zero | Real zeros are data, not an empty state: "0", "$ 0", "0". No helper text. A brand-new clinic sees "0 / $ 0 / 0" and the quick actions directly below are the call to action. |
| Error | The **whole row** is replaced by one `BloqueError` (§7) with message "No pudimos cargar el resumen del mes." (or the offline message). The 3 numbers come from one RPC, so they fail together. |
| Refreshing (pull) | Old numbers stay visible (no skeleton flash): `ref.watch(...).when(skipLoadingOnRefresh: true, skipLoadingOnReload: true)` semantics; only the `RefreshIndicator` spins. |

### 5. Próximas citas (`ProximasCitas`, DASH-02, D-07..D-09)

#### 5.1 Header row

```

```
- "Ver agenda" → `context.go('/agenda')` (switches to the Agenda tab; does not push). Visible in every state, including empty and error. Never locked.

#### 5.2 Data

- Up to **5** citas, clinic-wide, with `estado in (pendiente, confirmada)` and **`fecha_hora >= now()`** (checker fix A: `citas` has no `fin` column; an appointment already in progress drops off the list, accepted per research), ordered by `fecha_hora` ascending. No horizon: the 5 nearest, whether today or next month.

#### 5.3 Date separators

- Before the first row of each distinct day: a separator with `encabezadoDia(dia, hoy)` → "Hoy, lun 16/11", "Mañana, mar 17/11", "mié 18/11".

- The first separator is always shown, including "Hoy, …", so the date context is explicit.
- Spacing: `md` above every separator except the first (0), `sm` below.

#### 5.4 Row (`ProximaCitaFila`)

`AppCard(onTap: () => context.go('/agenda/${cita.id}'))` (cross-branch: `go`, precedent `recordatorios_providers.dart:92`), min height 72, padding `md`.


- **Multi-vet (D-07):** `esClinicaMultiVetProvider == true` → `VetAvatar`. Unlike the agenda, Inicio is always clinic-wide, so the mark shows whenever the clinic has more than one vet (no filter dependency). The avatar's semantics label "Dr(a). {nombre}" is merged into the row label.

- Gap between rows: `sm`.

## Accessibility & Interaction Notes

- **Touch targets:** every quick action, tappable metric card, cita row, "Ver agenda", "Reintentar" and "Agendar cita" is ≥ 48×48dp (`AppSpacing.touchTarget`). The Consultas card is not interactive and exposes no button role.
- **Semantics tree (top to bottom):** header (merged, `header: true`) → banner (existing) → 3 metric nodes (`button: true` only for Ingresos and Pacientes nuevos) → "Accesos rápidos" header → 4 buttons → "Próximas citas" header + "Ver agenda" button → separators (`header: true`) → rows (one merged node each, `button: true`) → alert cards (existing). Decorative icons (`storefront`, chevrons, empty-state icon, error icons, single-vet paw) are `excludeSemantics`.
- **Color is never the only signal:** chips have icon + text; the vet mark has initials + semantics name; the Paciente accent is backed by its label; error cards have icon + text.
- **Contrast:** all text pairs above are ≥ 4.5:1 in both modes; metric numbers in dark use `primaryHover` (5.49:1). **Known exception:** text buttons ("Ver agenda", "Reintentar") in light `primary` #C67139 are 3.03:1 on background / 2.94:1 on surface; on Inicio render them with `primaryText` locally, app-wide fix belongs to the core-theme plan (`textButtonTheme` foreground → `primaryText`). Decorative icons in dark: single-vet paw and empty-state icon use `mutedForegroundDark` (4.7:1), never light constants. White icons on all 4 circle fills are ≥ 3:1. The `AppStatusChip` tints are verified in dark mode by the sweep (see Sweep Rules SW-07).
- **Text scale up to 2.0:** metrics stack, quick actions go 2×2, row lines ellipsize at 1 line but the full text is in the semantics label; the greeting name allows 2 lines.
- **Focus order** follows the visual order; no traps.
- **Reduced motion:** no custom animations; skeletons are static (no shimmer).
- **Haptics:** none added.

## Sweep Rules (DASH-04, D-15..D-19)

The checklist every per-feature fix plan follows. It is the contract the `vetapp-brand-ui` audit scores against and the gates each plan runs.

### Process

1. **Audit first (one plan):** `vetapp-brand-ui` audits every feature against `DESIGN-REFERENCE.md`, the mockup and the rules below, and writes one findings table per feature: `rule ID · file:line · severity · finding · fix`. Features: `auth`, `home` (shell, Más), `patients`, `clients`, `clinical_history`, `appointments`, `vaccination`, `inventory`, `billing`, `plan`, `team`, `clinic`, plus `lib/core/widgets`.
2. **Fix plans grouped by feature**, parallelizable with **no file overlap**. `lib/core/**` fixes go in their own plan, run **before** the feature plans (they change shared rendering). A file belongs to exactly one plan.
3. **Severity handling (D-16):** BLOCKER and WARN are fixed in this phase, including the brand WARNs carried from VET-57 (Phase 6) and VET-78 (Phase 7). INFO goes to Linear (team VetApp, the feature's module label) unless trivial (< 5 min, no visual risk), in which case it is fixed inline.
4. **Behaviour freeze (D-19):** a fix may change only styling, widget choice, semantics and formatting. Any functional bug found is logged in Linear and **not** fixed in the sweep plan.
5. **Evidence per plan:** gates pass, full `flutter analyze` + `flutter test` green, and before/after emulator screenshots of each touched screen in **light and dark** mode stored in the phase `qa/` folder; results recorded ✅/❌ per task in `08-VALIDATION.md`.

### Rules

| ID | Rule | Severity | Fix |
|----|------|----------|-----|
| SW-01 | **Raw Material widget where a core one exists:** `ElevatedButton`, `FilledButton`, `OutlinedButton`, `TextButton` → `AppButton` (primary / outline / text / destructive); `AppBar` → `AppTopBar`; `TextField` / `TextFormField` → `AppTextField`; `Chip` / `ChoiceChip` / `FilterChip` → `AppFilterChip` (selection) or `AppStatusChip` / feature chip (status); `Card` → `AppCard`. | WARN (BLOCKER if it renders off-brand, e.g. default purple / square) | Swap to the core widget with the equivalent variant. If the core widget lacks a needed parameter (e.g. `AppTopBar` with `bottom:`, `AppTextField` with `inputFormatters`), add the parameter to the core widget in the core plan; never re-style the raw widget locally. |
| SW-02 | **Color outside tokens:** `Color(0x…)`, `Colors.*` (except `Colors.transparent`), `.withOpacity` on raw colors, outside `lib/core/theme/`. | BLOCKER if visible off-palette; WARN otherwise | `AppColors.*` or `Theme.of(context).colorScheme.*`. `Colors.white` → `AppColors.onPrimary`; `Colors.black*` → `foreground`/`textMuted`; `Colors.red*` → `destructive`; `Colors.green*` → `success`; `Colors.grey*` → `textMuted`/`border`. |
| SW-03 | **Typography outside roles:** `fontSize:`, `fontFamily:`, `GoogleFonts.*` outside `app_typography.dart`; `FontWeight` other than `w400`/`w600` (`bold`/`w700`/`w500` → `w600`). | WARN | Use the 4 roles: Display 28 (`displaySmall`), Heading 20 (`headlineSmall`/`titleLarge`), Body 16 (`bodyLarge`), Label 14/600 (`labelLarge`/`labelMedium`). `bodyMedium` 14/400 is allowed only for secondary lines already using it. |
| SW-04 | **Spacing outside scale:** numeric `EdgeInsets.*`, `SizedBox(height/width:)`, `spacing:` values not in {4, 8, 16, 24, 32, 48}; radii not `radiusSm/Md/Lg`. | WARN; INFO for 2px hairlines | `AppSpacing.*`. Allowed literals: icon sizes (16/20/24/32), avatar/circle sizes (24/40/56/64), skeleton bar sizes, 1-2px borders and strokes, the 72/88px list paddings documented in prior UI-SPECs. 12px → 8 or 16 (Phase 7 precedent). |
| SW-05 | **Touch target < 48dp:** `IconButton` with `constraints`/`visualDensity` shrink, `materialTapTargetSize: shrinkWrap`, `InkWell`/`GestureDetector` on a child under 48×48. | BLOCKER | `AppSpacing.touchTarget` min size, `ConstrainedBox(minWidth/minHeight: 48)` or padding. |
| SW-06 | **Missing semantics:** icon-only button without `tooltip`/`Semantics(label:)`; custom tappable without `button: true`; section titles without `header: true`; decorative icons not excluded; images without a label; status conveyed by color only. | BLOCKER for unlabeled actions and color-only status; WARN otherwise | Add tooltip/label in Spanish; `MergeSemantics` for rows; icon + text for status. |
| SW-07 | **Dark-mode contrast** (D-18, verify only): text < 4.5:1 or meaningful icon < 3:1 in dark mode, typically light-only `AppColors.*` text constants (`textMuted`, `textSecondary`, `primaryText`, `success`) rendered on `surfaceDark`. | WARN | Swap to the theme-aware equivalent (`colorScheme.onSurfaceVariant`, `textSecondaryDark`, `primaryHover` for money, `successBg` as text color for success in dark). No new tokens, no layout changes. |
| SW-08 | **Formats (Colombia):** dates not via `formatearFecha` (dd/mm/aaaa) or `formato_hora.dart` helpers; inline `DateFormat(…)`, `toString()`, `toIso8601String()` in UI; times in 24h; money not via `formatearCop` / `formatearCopCorto`; counts ≥ 1.000 not via `formatearMiles`; `'\$' +` concatenations. | BLOCKER for wrong format shown to users; WARN for inline formatting that happens to match | Use the helpers. |
| SW-09 | **Copy:** "Próximamente", "Factura/factura/Facturación" in UI strings, English strings, exclamation marks, Title Case buttons, "usted" toward the vet (client-facing text keeps "usted"). | BLOCKER for "Factura" and "Próximamente"; WARN otherwise | Rewrite per prior UI-SPEC copy tables. |
| SW-10 | **Card / chip anatomy drift** from DESIGN-REFERENCE: hard shadows, square corners, inputs with hard borders where the theme fills, status pills not using the tinted-fill + strong-text pattern. | WARN | Use the core widget defaults; do not tune per screen. |

**Exemptions:** `lib/core/theme/**` (token definitions); `lib/core/widgets/**` internals may wrap raw Material widgets (that is their job) but are themselves subject to SW-02..SW-07 (e.g. `AppStatusChip`'s 6px padding/gap is INFO, not fixed unless trivial); test files; generated files; PDF builders (`*_pdf_service.dart`) use the `pdf` package's own styles and are checked only for SW-08/SW-09.
