## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile app (authenticated JWT) -> PostgREST RPC registrar_consulta | Vet controls every argument (mascota id, free text, vitals, peso) |
| mobile app -> PostgREST table consultas | A modified client could try direct insert/update/delete bypassing the RPC |
| anon key holder -> PostgREST | Public key; must not reach consultas or the RPC |
| SQL Editor (postgres) -> smoke test | Privileged session; must leave no residue |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-RLS | Information Disclosure | consultas select | mitigate | consultas_select scoped by es_veterinario() + mascotas.clinica_id = mi_clinica_id(); smoke G9, H1, I1 |
| T-03-RPC | Elevation of Privilege | registrar_consulta | mitigate | security invoker (caller RLS applies inside), explicit vet/clinic guard, mascota-ownership guard (23503), revoke from public, anon; smoke G4, H2, I2; probe asserts anon 401/403 |
| T-03-APPEND | Tampering / Repudiation | consultas update/delete (HIST-04) | mitigate | No update/delete policy exists at all; smoke G10, G11, H3, H4 prove 0 rows even for the owning vet |
| T-03-SPOOF | Spoofing | consultas.veterinario_id on direct insert | mitigate | Insert policy requires veterinario_id = auth.uid(); RPC sets it from auth.uid(); smoke G7 |
| T-03-PESO | Tampering | consulta weight vs mascota_pesos (D-02) | mitigate | Single plpgsql function = one transaction; peso check > 0 on both tables; smoke G1 (no peso -> no row), G2 (peso -> exactly one row) |
| T-03-INPUT | Tampering | blank/invalid clinical fields | mitigate | check constraints on diagnostico/tratamiento/vitals; nullif(trim()) for optional text; smoke G3, G5, G6 |
| T-03-SMOKE | Tampering | smoke test residue in the real DB | mitigate | Script always ends with RAISE EXCEPTION, rolling back every insert |
